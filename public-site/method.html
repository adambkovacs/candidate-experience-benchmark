Method and limits

How we ran the test, and what it cannot tell you.

AI wrote these fictional comments and drafted the reference answers. A person checked all 60 answers; some remain disputed. Historical scores retain the original reference version. The results describe this test set, not performance with real candidates.

How the test was scored

Prompt versions: P0 is the base task; P1 and P2 add different instructions. Every score is out of 60, even when a run saved fewer responses. AI drafted the reference answers; a person checked all of them. Historical scores retain the original reference version.

Time: Server inference time appears only when a provider reports it. The technical run detail shows recorded client request durations, their sum and the number of timed requests. Some requests classified one comment; others classified a batch. The sum does not show how long concurrent work took from start to finish. Local times reflect the test machine and workflow.

Cost: Reported API charges, price estimates and possible charges without a known bill are labeled separately. Subscription fees are not split across runs. An API price estimate is not an observed charge.

Questions you may have

What do "model", "prompt" and "run" mean?

The model is the AI system. A prompt is the set of instructions and the comment it receives. A run is one recorded attempt to classify this set of comments using a particular setup.

What are tokens, and why do they matter?

Tokens are small pieces of text a model reads or produces. Hosted services often price requests by input and output tokens. Extra reasoning can add output tokens even when the final answer is short.

Did every model process comments in the same way?

No. Some calls contained one comment; subscription runs sometimes used batches. Specialist APIs returned choices directly. Local runs used this project's machine. We keep these differences visible because they affect comparisons.

What were the models allowed to see?

The comment and the task instructions, including the label definitions. They did not receive the reference answer or another model's previous prediction. We compared outputs with the references afterward.

Does a valid response mean the answer matched?

No. Valid means the response followed the format needed for scoring. Agreement is counted separately against the saved reference answers.

Do score changes show that one prompt is better?

You can compare saved outcomes, but differences in where and when runs were made, missing records, and other settings make it hard to attribute a score change to the prompt alone. Five earlier local Qwen comparisons lack logs for the base runs. Their comparison reports show the saved changes and explain the missing evidence.

Why can a complete run have invalid responses?

Complete means a response was saved for each of the 60 comments. Some saved responses did not follow the required format, so they could not be scored.

Why is a price missing?

Some services do not report a charge for each run. An unavailable charge does not mean the run was free. Estimates and upper bounds are labeled separately.

Can I use these scores to choose a hiring tool?

No. This small fictional set and its provisional answers do not measure performance with real candidates or the effect of using a model in hiring.

The reference answers were checked too.

A person checked all 60 reference answers. DEV-006 has a proposed serious-concern correction; DEV-013 and DEV-030 remain judgment calls. The charts retain the original answers so historical results remain inspectable.
