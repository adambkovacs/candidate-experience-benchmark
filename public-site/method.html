How the test ran.

We wrote 60 short, fictional comments from job candidates and asked every model the same four questions about each one. AI wrote the comments and drafted the reference answers. A person checked all 60, and three labels are still disputed. Every number on this site describes these 60 reviews and nothing wider.

The four questions

  1. How was the experience? Positive, negative, mixed, neutral, or can't tell.
  2. Does someone need to follow up? Yes, no, or can't tell.
  3. Does it report a serious concern? Harassment, discrimination or a privacy breach, for example. A bad experience alone does not count. Can't tell is for a serious issue that is alleged but underspecified.
  4. Could it work as a testimonial? Yes, no, or can't tell.

The labelling guide fixes each boundary, and the reference review records every label we argued about.

How a match is scored

A review counts as matched only when all four answers agree with the reference. The denominator is always 60. A missing, failed or malformed answer scores as a miss, so a run that saved 57 usable answers can match at most 57. Explore counts format and agreement separately.

Three prompts

P0 is the base task. P1 adds classifier instructions with the label definitions. P2 adds step-by-step decision rules. Decision models received the same instructions inside their native Choice questions. No model saw the reference or another model's answer.

How many passes, and which ones broke

The site holds 1,004 saved run-passes. 252 configurations ran each prompt three times with fresh requests: 50 decision-model configurations and 202 general ones. In 241 of them every pass returned at least 50 usable answers. The other 11 contain a partial or failed pass: AnyJev generated, Qwen 0.6B on the SDK, SemIf generated P1, OpenJev generated-on P2 pass 3 at 47 usable answers, and Jev's P2 pass 2, which stopped after 17 answers on a rate-limit error.

An interrupted pass has no score of its own. Where a continuation finished the remaining reviews, Explore shows the combined result and marks it.

Three labels are disputed.

A person checked all 60 reference answers. Three stayed open after a second review.

DEV-006
Same as last time. That thing happened again and it still isn't sorted. The reference says can't tell on serious concern. The review proposes no, because "that thing" names no serious conduct.
DEV-013
A friend told me they heard this firm asks inappropriate questions. My own interview was straightforward, and I have no complaint about it. The reference says neutral. Positive is defensible, and the guide does not fix that boundary.
DEV-030
The accessibility issue from the assessment has been dealt with, I think. Someone said it was fixed, but I don't know whether that means I get another assessment or just that they've closed the ticket. The reference says neutral, and the sentiment is a judgment call.

Every published score uses the original labels. Scores under the alternative labels are on Explore.

The whole study cost $12.65 on OpenRouter.

OpenRouter billed $12.653729 across 15,135 saved generations. Up to $3.88 more sits in reservations for requests whose id was never saved, mostly failed or interrupted calls. That is a ceiling on what we may owe, never a charge.

The seven decision models' full series of nine passes each cost $1.2013 in known charges, plus up to $0.1285 of unrecorded reservations.

A Jev pass through OpenRouter cost $0.00589092 for 140,260 input tokens, and it matched 54, 53 and 52 over three passes. On TypeSafe's direct API, Jev scored 54 on its first pass and there is no bill. Claude and Codex ran on subscriptions, so their costs are API-rate equivalents. Every cost on this site is a provider charge, an API-rate equivalent, or unknown. A missing cost is unknown, never zero.

Corrections

classification-bench

classification-bench, the tool that ran this test, runs it on your own cases, labels and questions. It saves every request, answer, failure and charge, which is how every number on this site traces back to a saved answer.

Terms used on this site
Run-pass
One model, one prompt, one pass over all 60 reviews.
Configuration
One model with its route, effort and batch size held fixed.
Decision model
A model built to return one label from a fixed list in a single pass, through a native Choice interface.
Tokens
The pieces of text a provider bills for. Reasoning adds output tokens even when the answer is one word.
Request time
Measured by our client, network included. Providers did not report inference time, so the site makes no speed claim.
