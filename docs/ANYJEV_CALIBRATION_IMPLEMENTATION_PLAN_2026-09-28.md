# AnyJev calibration repeat implementation plan, 28 September 2026

This plan separates the saved [cached-score L1 study](../results/anyjev-cached-l1-cv5-2026-09-24/README.md) from the saved [native L2 study](../results/anyjev-l2-cv5-hf517-v1-2026-09-24/README.md). The former has no new model calls; the latter fits heads and predicts held-out records. Neither is a direct, unlabeled P0 run. The [admission audit](ANYJEV_CALIBRATION_NEXT_ADMISSION_2026-09-28.md) supplies the eligibility evidence. No stage is admitted by this document.

## Decision and order

1. **L1 cached refit, optional offline check.** If useful, run the exact saved five-fold `TemperatureScaler.fit/apply` computation twice into new exclusive output directories, comparing each result with the original. Call the result *cached-calibration reproducibility*, not native inference repeatability. It reuses the same frozen L0 score vectors and provisional labels; repeating it cannot create new L1 model-call evidence. There is no eligible direct-native `anyjev-qwen06-l1` first pass in the saved record. Do not put these refits into the native three-pass flip denominator.
2. **L2 native, first implementation target.** Treat the successful 60-row five-fold collection as a *candidate* pass 1 only if an offline parity audit confirms that a new pass can retain the exact staged procedure, fitted-head API, model/runtime/source bindings, fold order, and label boundary. Prepare two new, separately named passes. Each pass fits its own five sets of four heads; never load a prior pass's head. For each pass, perform a three-record smoke on DEV-001–003 (folds 1, 4, 5), inspect and approve it, then collect the other 57 held-out predictions using the three smoke heads and rows unchanged. The earlier [failed unadapted smoke](../results/anyjev-l2-cv5-2026-09-24/smoke.operations.jsonl) remains failed evidence, not a pass to repair or retry.
3. **Direct native L1, required next design.** First specify and test how native L1 calibration vectors and artifacts are fitted and loaded for each fold, with source and model controls frozen. No such first pass exists. It must therefore begin a distinct fresh three-pass series, not inherit the cached L1 result or the L2 heads. Do not create it by changing an L2 level flag without validating the upstream calibration API and actual calls.

## New L2 runner contract

Implement a new repeat-specific controller and tests; leave the historical controller, manifests, and results immutable. Freeze one manifest per new pass with exact input/fold/protocol/source/model/runtime hashes, output identity, smoke IDs, expected fold order, and common GPU lock path. Root reviews each manifest before dispatch. A pass is one smoke-plus-full staged five-fold procedure, not 60 fresh calls in a single stage. Use the current shared GPU lock before native work; fail closed if another native owner holds it. No download or artifact substitution.

The existing controller journals `fit_head` and `predict` starts and finishes, and fsyncs projected rows; it does **not** retain an unprojected per-call native response before `predict_one` validates it. The new runner must add durable raw capture for every fit result and every per-question held-out decision before projection/validation, with a stable fold, question, record, artifact, and operation identity. Claim each operation durably before the call; append raw with fsync before parse or scoring; append a decision/status after parse. If a call started without a complete raw result, preserve it as unknown and stop that pass. If a complete raw result is invalid, retain its raw/status and follow a frozen invalid-continuation policy reviewed before execution. Never retry an uncertain operation or skip a previously required fold/ID. The old 60-row pass remains comparable on its recorded projections and journals, but the stronger new raw evidence is an explicitly disclosed instrumentation difference.

A new pass's smoke must fit exactly the three folds holding DEV-001–003, save their 12 head artifacts, and produce exactly those three raw and projected held-out rows. Root inspection binds raw/journal/rows/artifacts and approves a separate full-stage receipt. Full stage checks the smoke hashes and head provenance, reuses them byte-for-byte, fits the other two folds, and predicts exactly the other 57 IDs in the historical outer-fold order. Freeze a terminal collection manifest binding 60 unique out-of-fold IDs, five fold artifacts/20 fits, raw captures, journals, both admissions, runtime, and incomplete/invalid/unknown positions. A stopped stage is a partial observation; do not manufacture a 60-row denominator or promote it to a completed pass. Preserve historical [full.jsonl](../results/anyjev-l2-cv5-hf517-v1-2026-09-24/full.jsonl) and [full.operations.jsonl](../results/anyjev-l2-cv5-hf517-v1-2026-09-24/full.operations.jsonl), including numerical warnings and earlier unknowns as recorded.

## Label boundary and the comparability choice

Training labels are allowed **only** for each fold's 48 training IDs and four head fits. The model request for each of its 12 held-out IDs contains input feedback only. The existing `narrow_training_labels`/`fit_fold` guard passes just 48 labels to the fit and `guarded_backend` checks the rendered prompts. Nevertheless, historical `run()` reads the whole provisional-label file in the same process before narrowing it. That supports a code-enforced training/prompt boundary, not process-level inability to access held-out labels.

The L2 repeat uses the historically matched code-enforced boundary and discloses that there is no OS-level label isolation; test that fit receives exactly 48 train labels and feedback, and that native prompts contain only held-out feedback. A stronger per-fold process boundary may be built later as a separate fresh three-pass protocol: its only label-bearing input would be the 48 training rows, its held-out input `{id, feedback}`, and its evaluator separate after raw output is sealed. Do not silently substitute that protocol for the historically matched run. Never place references, label-derived examples, prior predictions, or other folds' test labels in inference requests. Evaluate accuracy/calibration only after the raw native outputs are saved.

## Implementation and admission checks

Create focused tests before dispatch for fold membership and pair grouping; exact historical protocol/runtime/source hashes; no label in held-out request or prompt; 48-label fit scope; distinct artifacts per pass; smoke folds 1/4/5; smoke-to-full reuse and 3+57 composition; raw-before-parse and fsync ordering; unknown started call stops without retry; known invalid retention; exclusive output identities and cross-process GPU lock. Fake backend tests must exercise actual controller gates, not only injected failures. Reparse each saved raw decision and compare projected labels/probabilities with rows. Check all requested IDs and source bindings offline without loading the model.

First audit historical parity against actual current runtime and controls; use the saved L2 run as candidate pass 1 only when they match, otherwise declare a fresh three-pass series. Root then reviews the frozen manifests/controller/tests and current GPU owner. Admit one smoke at a time under the common lock, inspect the three raw calls and head artifacts, sign a full-stage receipt, and only then collect the remaining 57. Finish and verify pass 2 before admitting pass 3. Publish a native L2 repeat report only when each intended pass is terminal; show missing/invalid/unknown positions rather than silently excluding them. Timing includes fit, model load, and staged collection, so it is not pure per-record inference latency. The 48-label heads use provisional development labels, the historical inner five-fold split is ungrouped, and numerical warnings were observed; any three-pass stability result remains exploratory on these records.
