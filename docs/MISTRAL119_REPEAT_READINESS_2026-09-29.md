# Mistral Small 4 119B repeat readiness, 29 September 2026

The two hosted configurations, `openrouter-paid-mistral-small4-119b-none` and `openrouter-paid-mistral-small4-119b-high`, remain in scope. Neither has a completed P0 development baseline or an eligible historical first pass. A matched P0/P1/P2 repeat study therefore needs a distinct three-pass series for each effort. This is a readiness assessment only: no new inference, allocation, or execution manifest was created.

The [run registry](../results/openrouter-paid-run-registry.json) identifies `mistralai/mistral-small-2603` on Mistral's `mistral/zdr` endpoint with quantization reported as `unknown`. The [sanitized original smoke records](../public-evidence/provider-errors-v1/results/openrouter-partition-mistral119-none-2026-09-23/smoke.jsonl) and [high-effort counterpart](../public-evidence/provider-errors-v1/results/openrouter-partition-mistral119-high-2026-09-23/smoke.jsonl) bind separate request hashes for the two efforts. Both requests use one system instruction and one feedback-only user message, temperature 0, 4,096 maximum output tokens, no streaming, a strict JSON schema, and an exact provider guard with fallback disabled. The provider price ceiling is $0.15 per million input tokens and $0.60 per million output tokens. Reasoning is `{"enabled":false,"effort":"none"}` or `{"enabled":true,"effort":"high"}`. The saved endpoint has 262,144 context tokens, prompt price $0.00000015 per token, completion price $0.0000006 per token, and no asserted quantization beyond `unknown`.

At the 29 September read-only check, OpenRouter's [model catalog](https://openrouter.ai/api/v1/models) listed one exact model with supported efforts `none` and `high`; its [endpoint catalog](https://openrouter.ai/api/v1/models/mistralai/mistral-small-2603/endpoints) listed `mistral/zdr` at status 0 with the same prices and context bound. Those public metadata results do not prove inference capacity. The [second recovery checkpoint](../results/mistral119-recovery-prep-v2/README.md) records that both configurations still received HTTP 429 on DEV-001 after roughly 1 hour 50 minutes of cooldown despite an available-looking endpoint. DEV-002 and DEV-003 were never sent in either second-checkpoint smoke. The [failed smoke inspections](../results/mistral119-recovery-prep-v2/none-smoke-inspection.json) and [high inspection](../results/mistral119-recovery-prep-v2/high-smoke-inspection.json) reject development admission.

Across the saved original and recovery files, five `none` and three `high` DEV-001 smoke requests ended in HTTP 429. Each relevant saved attempt carries a $0.04177920 full reserve with no observed provider charge; it is an unknown-charge bound, not an invoice amount or a model-output cost sample. The [second recovery reconciliations](../results/hosted-recovery-budget-v2/mistral119-recovery-v2-none-reconciliation.json) and [high reconciliation](../results/hosted-recovery-budget-v2/mistral119-recovery-v2-high-reconciliation.json) each account for one such bound and seal that child partition. Prior failures and their ledger entries must remain distinct from any new series. The [paired-baseline audit](../results/prompt-pairing-reconciled-baselines-2026-09-24.json) records zero prediction records for both configurations and marks their historical prompt comparison ineligible.

One request's conservative reserve follows the [paid runner's full-context formula](../scripts/openrouter_paid_benchmark.py): 262,144 × $0.00000015 input plus 4,096 × $0.0000006 output = **$0.04177920**. Three smoke reservations require at most $0.12533760 before settlement. A new matched series would schedule three passes × three conditions × (three smoke + 60 development) = **567 calls per effort**, or 1,134 for both. Reserving every call at the full-context maximum would be $23.68880640 per effort ($47.37761280 together). This is a stress bound, not a forecast or a proposed child cap: sequential known-charge settlement may release capacity, whereas an unknown charge retains its entire bound. With no successful Mistral119 response, there is no defensible observed-token or known-charge proxy for the full study. The existing $10 aggregate cap and any active allocations must be checked afresh before proposing a child; the earlier [pending matrix](HOSTED_PENDING_MATRIX_2026-09-29.md) is a dated capacity snapshot.

To prepare reviewable plans offline:

1. Build two independent, input-only 60-ID rosters and verify every P0 request against the original saved request body, exact route, schema, instruction bytes, and feedback. Keep reference labels and earlier predictions out of all requests. Do not count any failed smoke as a fresh pass.
2. Compose P1 and P2 from each exact P0 system instruction with the [frozen variant bundle](../prompts/variants-v1/manifest.json) using the [composition helper](../scripts/frozen_prompt_variants.py). Bind the resulting bytes, the strict output schema, inputs, route, sampling, reasoning effort, seed policy, and 4,096-token limit. No Mistral119 P1/P2 request bodies or inspected development stages exist yet; these must be created and verified rather than inferred from another model's run.
3. Freeze separate three-pass schedules in the order P0/P1/P2, P1/P2/P0, and P2/P0/P1, with a three-record smoke inspection before each 60-record development stage. Keep invalid outputs, service failures, missing positions, timing, token usage, and known versus unknown charges in the fixed 60-record denominator. A changed provider or route needs a separately named configuration and new comparability decision.
4. Review an execution controller with immutable source and request hashes, an exclusive child-ledger lock, atomic per-request reserve, durable raw HTTP evidence before parsing, no automatic retry or replay, exact predecessor gates, and a stop before any call whose full reserve cannot fit. Recheck the live model and endpoint metadata and make an explicit capacity/cooldown decision before a separately admitted smoke. Only real successful smoke responses can support a future charge proxy; catalog status alone cannot.

These steps prepare the remaining work without excluding Mistral119. The current barrier is observed upstream 429 capacity plus the absence of a funded, reviewed fresh-series plan; changing the model or silently replaying DEV-001 would not close it.
