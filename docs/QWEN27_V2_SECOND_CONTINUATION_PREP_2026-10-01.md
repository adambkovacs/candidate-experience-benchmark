# Qwen27: second continuation prepared after route-check aborts

The first continuation stopped before sending its next request in both Qwen27 configurations. The [medium journal](../results/repeatability-v1/qwen27-fresh-matched3-v2/interruption-continuation-v1/medium/fresh3/P0/suffix/suffix.journal.jsonl) contains 16 settled attempts, DEV-023 through DEV-038, then an abort before DEV-039. The [xhigh journal](../results/repeatability-v1/qwen27-fresh-matched3-v2/interruption-continuation-v1/xhigh/fresh3/P1/development/development.journal.jsonl) contains eight settled P1 attempts, DEV-001 through DEV-008, then an abort before DEV-009. Neither abort created a reservation for the next ID. Their [medium](../results/repeatability-v1/qwen27-fresh-matched3-v2/interruption-continuation-v1/medium/terminal-reconciliation-after-route-change.json) and [xhigh](../results/repeatability-v1/qwen27-fresh-matched3-v2/interruption-continuation-v1/xhigh/terminal-reconciliation-after-route-change.json) child allocations are sealed and reconciled with zero new unknown-charge bound. The original medium DEV-022 and xhigh DEV-037 failures remain separate, with their earlier unknown-charge bounds intact.

The [first controller](../scripts/qwen27_v2_interruption_continuation.py) compared complete model and endpoint objects after each live check. The [medium abort review](QWEN27_MEDIUM_CONTINUATION_ROUTE_ABORT_2026-10-01.md) found that a later public sample differed only in rolling uptime fields. The exact metadata at either rejected check was not captured, so that sample does not prove the abort's precise cause.

The proposed [second controller](../scripts/qwen27_v2_second_continuation.py) is a separate version. It checks the same selected model, provider, reasoning support, price, context and token limits, supported parameters, maximum reserve, and every frozen request payload before each send. It compares the nine endpoint fields used by the original controller rather than the complete endpoint object. It records the selected public model and endpoint metadata, including uptime, before any request intent or reserve. A rejected route leaves that observation and the changed experimental field names in the new stage journal. The original request payloads and response parser stay unchanged.

The new schedule is descriptive. It does not repair the original failed requests or turn the interrupted configurations into clean matched three-pass series. The controller verifies the first continuation's exact hashes, ordered attempts, raw captures, child settlements, and master reconciliation before freezing. It also requires a new partition ID and child budget, a new frozen manifest, and a separate root review receipt for each stage. A later full P1 stage still requires the root to inspect its three-record smoke unchanged.
