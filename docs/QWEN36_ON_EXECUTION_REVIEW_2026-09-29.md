Its status is `offline_frozen_not_approved`. The proposed $1.50 child partition is **unfunded**; no provider request, key read, or budget allocation was made during preparation.

Before a future stage, the executor requires its exact frozen plan, a stage-specific root-review receipt, the historical continuation-policy source, a funded child budget manifest and an available exclusive child ledger. The live public catalog must match the saved model, AkashML route, fp8 quantization, status, supported parameters, context limits and pricing. It must advertise `reasoning: {"enabled": true}` and permit the exact frozen request bodies. The maximum reservation is $0.0299008 per call; it is reserved under the ledger lock before a network request. A stage with an existing claim cannot be replayed. Only one ordered phase per condition is admitted; each 60-record development phase requires a distinct three-record smoke, its durable raw evidence, and an inspection receipt.

The reviewed transport writes at most 16 MiB of HTTP response bytes, status and selected headers to a durable raw sidecar **before** parsing a 200 response. The same bound applies to HTTP errors. A malformed or truncated response with unknown billing retains the full reservation and stops the phase. A known-billed invalid output is retained and stops under this new plan's failure policy. Attempt records keep the returned model, provider, usage, charge, client duration and response diagnostic when available; unavailable charges remain null, never zero. Successful phase closure rechecks attempt IDs, raw bodies, exact requests, cost and usage, and journal order. This is a request-to-record client timing boundary, not pure model inference time.
