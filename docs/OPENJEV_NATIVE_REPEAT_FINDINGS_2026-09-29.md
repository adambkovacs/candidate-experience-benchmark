# OpenJev native repeat: fixed triplet and first adaptive pass

All three fresh fixed-mode passes completed 60 development reviews with valid outputs. Each matched all four provisional reference fields on **53/60** reviews: sentiment 56/60, follow-up 60/60, serious concern 57/60 and testimonial potential 60/60. Every pair had zero flips across 60 shared valid reviews, and no four-field prediction changed across the three passes. The all-field range is 53–53/60. Identical answers on this fixed set do not prove deterministic behavior on other inputs or runtimes.

The same seven reviews missed at least one reference field in each pass. Three mixed-sentiment references were classified as negative; one insufficient-information sentiment reference was classified as neutral. Three insufficient-information serious-concern references were classified as no. Follow-up and testimonial decisions matched the provisional references for all 60 reviews in every pass. Those references are provisional AI-reviewed labels, not independent human ground truth.

The first fresh adaptive pass also completed 60 valid reviews. It matched all four reference fields on **52/60**: sentiment 54/60, follow-up 60/60, serious concern 57/60 and testimonial potential 60/60. Four mixed-sentiment references were classified as negative, one neutral reference as negative, and one insufficient-information reference as neutral. Three insufficient-information serious-concern references were classified as no. Relative to fixed fresh1, adaptive changed four sentiment answers: DEV-019, DEV-020 and DEV-030 lost agreement, while DEV-059 gained it. This is a comparison between modes on the same records, not an adaptive repeat-stability estimate or an isolated causal effect.

Fixed mode is complete within the [nine-phase fresh roster](../results/repeatability-v1/openjev-native-fresh-v1/manifest.json). Adaptive has one closed fresh pass and needs two more; thinking needs all three. Neither mode has a fresh pairwise flip rate or three-pass range yet. Historical observations cannot fill those slots: the historical fixed run had an interruption, and the prior cache state for historical adaptive and thinking was not observed. Historical fixed scored 52/60 all-field matches; its difference from fresh fixed is descriptive, not a matched-repeat change.

The [public report](../public-site/openjev-native-repeats.json) binds each closed pass's three-review smoke inspection, root stage receipts, 60-row development completion, raw responses, projected records and request journal. The [adaptive completion](../results/repeatability-v1/openjev-native-fresh-v1/openjev-adaptive/fresh1/P0/development.completion.json) is a separate stage from the fixed triplet. The reporter verifies those files, frozen requests and public source hashes before scoring. The frozen manifest records local runtime and model-asset hashes; a public checkout cannot rehash private model weights.

The 60 development client HTTP request times sum to 239.77, 254.38 and 255.14 seconds for fixed fresh1, fresh2 and fresh3, and 285.41 seconds for adaptive fresh1. These are wall-clock request times, not isolated model inference or the full time to load the model and run both stages. Response usage reports 123,989 input tokens and zero output tokens for each closed pass; the latter is a reported field, not evidence that generation used no computation. Actual adaptive rereads and local hardware or electricity cost were not measured. Local cost remains unknown, not zero.
