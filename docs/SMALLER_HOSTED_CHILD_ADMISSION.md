# Smaller hosted child admission

Prepared offline on 2026-09-29. The original [Qwen off](QWEN36_OFF_FRESH_REPEAT_ADMISSION.md) and [DeepSeek low](DEEPSEEK_LOW_FRESH_REPEAT_ADMISSION.md) fresh-series plans each propose a $0.30 ceiling. The new [Qwen v2 runner](../scripts/qwen36_off_fresh_repeat_execution_v2.py) and [DeepSeek low v2 runner](../scripts/deepseek_low_fresh_repeat_execution_v2.py) allow an actual child allocation from one full per-request reserve through that $0.30 ceiling, inclusive. Their frozen v1 runners remain unchanged. Each v2 runner has its own code binding, manifest schema and output directory, so a v1 manifest cannot be used as a v2 execution manifest.

A possible pair is $0.15 for Qwen off and $0.25 for DeepSeek low, encumbering $0.40 in total. Qwen's historical three-set known-charge and smoke proxy is $0.0827355. Adding its full $0.0299008 request reserve gives $0.1126363, leaving $0.0373637 inside a $0.15 child. DeepSeek low's proxy is $0.11747781. Adding its full $0.1069056 reserve gives $0.22438341, leaving $0.02561659 inside a $0.25 child. These are planning margins, not upper bounds on future charges. Two unknown DeepSeek low charges, higher observed charges, or provider failures could stop the series before all nine phases. Neither runner retries or increases a child allocation automatically.

At the offline check, the [master ledger](../results/openrouter-paid-budget.jsonl) accounted for $9.99916368150 under the existing $10 cap, with a $0.46 DeepSeek off child still active and $0.00083631850 unallocated. The pair cannot be allocated at that state. After that child is reconciled, the allocator must confirm at least $0.40 of unallocated capacity and no pending or blocked charges. Released capacity is not assumed. A reviewed plan and v2 manifest must be frozen against their exact current sources before allocation; both plans should be prepared and frozen before the first child is added, because an allocation changes the ledger snapshot used by plan equality at freeze. No higher aggregate cap is authorized.

The actual partition cap is checked in `prepare` before key access, a stage claim or an HTTP call. A phase review receipt binds the actual budget manifest hash, partition ID, stage, execution manifest hash and v2 runner hash. The existing [partition allocator](../scripts/paid_budget_partitions_v2.py) binds each child to the master ledger and enforces atomic reservations and reconciliation. The runner retains raw responses, per-request timing, usage, observed cost or unknown bounds, and the prior smoke and phase gates. Any request that cannot reserve its full bound stops before inference. Qwen off and DeepSeek low still use only the existing 60 reviews; reference labels remain outside inference.

The [offline tests](../tests/test_smaller_hosted_child_admission.py) call both real v2 `prepare` functions using temporary plans, manifests and receipts. They accept $0.15 and $0.25 children, reject caps above $0.30 or below one full reserve before key access or a claim, reject a stale budget receipt hash, and verify unchanged requests and v2 code bindings. No paid call, production manifest, child allocation or inference was made in this preparation.
