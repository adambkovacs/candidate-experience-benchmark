# Cloudflare Clef: native decision benchmark preparation

Cloudflare released [Clef and Clef Flash](https://blog.cloudflare.com/clef-decision-models/) as decision models on Workers AI on 1 October 2026. Their published benchmark results are useful context, but they do not measure agreement with this project's recruitment-feedback labels. This project has **no Clef inference result**. The [offline preparation script](../scripts/clef_native_preparation.py) builds and hashes requests from the existing 60 fictional development reviews; it has no transport, credential, or scoring path. The saved [input-only manifest](../results/clef-native-v1/preparation.json) is the exact artifact the smoke runner checks before dispatch.

| Model | Workers AI route | Request `model` | Context | Published input price |
| --- | --- | --- | ---: | ---: |
| [Clef](https://developers.cloudflare.com/workers-ai/models/clef/) | `@cf/cloudflare/clef` | `clef` | 65,536 tokens | $0.24 per million tokens |
| [Clef Flash](https://developers.cloudflare.com/workers-ai/models/clef-flash/) | `@cf/cloudflare/clef-flash` | `clef-flash` | 65,536 tokens | $0.09 per million tokens |

Cloudflare's [model pages](https://developers.cloudflare.com/workers-ai/models/clef/) specify one `state` and 1–64 typed questions; `choice` questions have labeled `criteria` and return a chosen label with per-option probabilities. The adapter submits the [existing four recruitment judgments](../scripts/jev_benchmark.py) as four native `choice` questions in one request for each record. P0 retains those instructions. P1 and P2 append the frozen [native instruction variants](../scripts/jev_native_prompt_variants_v1.py) to each question; state, label options, model route, and all other wire fields stay the same. This is a native question-instruction comparison, not a chat system-prompt comparison. The state contains only the review text and policy. Reference labels remain offline.

The plan covers P0, P1, and P2 with three separately dispatched fresh passes for each model. Each of the nine model-specific phases would first send DEV-001–003 as a three-record smoke; a reviewed, terminal smoke would be required before that phase's 60-record development run. The same 60 synthetic reviews are reused across passes. Missing, invalid, provider-failed, and never-sent positions must remain in a fixed 60-position score; answer-change calculations may use only shared valid records. Native probabilities and confidence should be retained alongside categorical choices, then scored offline against the frozen provisional reference key. No phase may borrow a result from another model, route, prompt, or pass.

Cloudflare's [pricing table](https://developers.cloudflare.com/workers-ai/platform/pricing/) lists input-token prices for these models, with no separate output-token rate. As a conservative *planning reservation*, the script multiplies the published 65,536-token context by the input rate and rounds **each request** up to the next micro-dollar. Nine phases × (3 smoke + 60 development) = 567 requests per model. That calculation is **$8.918343 for Clef and $3.344733 for Flash, $12.263076 together**. It is neither observed spending nor a verified provider-enforced cap. Actual tokenization, account billing, plan access, and any daily free allocation have not been checked. A shorter live scope needs its own explicit stage budget; the existing OpenRouter and TypeSafe budgets do not authorize Cloudflare calls.

The first proposed admission is only **fresh1/P0 DEV-001–003 for each model**, six requests total. Its rounded full-context hold is $0.047187 for Clef plus $0.017697 for Flash, **$0.064884** together. A separate **$0.10 Cloudflare cap** is proposed for review, not approved or allocated. A later full development phase requires another review after both smokes. If Cloudflare returns credible input-token usage, retain it as observed usage and reassess later estimates; do not replace a fail-closed reservation ceiling merely with an average from three cases. A tighter reservation needs a validated bound for each future request or a provider-enforced limit.

Cloudflare's [REST guide](https://developers.cloudflare.com/workers-ai/get-started/rest-api/) requires an account ID and an API token, and documents the bearer-authenticated `/client/v4/accounts/{ACCOUNT_ID}/ai/run/{MODEL_ROUTE}` endpoint and `success`/`result` response envelope. A custom token requires Workers AI Read and Edit permissions. The smoke runner accepts `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` or the existing codebuild aliases `CF_ACCOUNT_ID`/`CF_API_TOKEN` at execution, from its process environment or `--env-file`; nonempty process values take precedence, then canonical names within the same source. The file is parsed as data, never sourced as shell code. The offline preparation script reads neither. Empty canonical placeholders are present in [`.env.example`](../.env.example). On 2 October 2026, the parent codebuild `.env` was found to contain the `CF_` names, and a connected Cloudflare app successfully listed the account and both Clef model routes. This confirms credential availability and account/model visibility, but not a paid REST call or billing authorization. No secret value is recorded here. The private `classification-bench` Clef adapter was read as a design reference only; its credentials, account, and spending authority are separate and were not used here.

The [smoke runner](../scripts/clef_native_smoke_runner.py) implements the first stage only: `fresh1/P0/smoke` for one pinned model per invocation. It requires the exact saved input-only manifest, a separate reviewed grant binding that manifest, runner version, account-ID hash, both published-rate sources and the $0.10 cap, and the two Cloudflare environment variables. It refetches the reviewed billing source bytes before dispatch and refuses a changed hash. Its HTTPS transport blocks proxies and redirects; it has no automatic retry. A single locked Cloudflare ledger reserves the full-context hold before each send. Reservations remain held as **unknown charge** even if a response reports token usage, because usage does not prove the account's exact USD charge. Each attempt has an immutable ID and durable journal, redacted raw response, parsed probabilities, and a terminal completion. A crashed or partial stage cannot be replayed under the same stage path or ledger identities.

The grant schema is `clef-native-initial-smoke-grant-v1`, with `approved: true`, `authorized_by_user: true`, a named `reviewer`, `plan_sha256`, `runner_sha256`, `account_id_sha256`, both `billing_source_sha256` values, the two published input rates, `models: ["clef", "clef-flash"]`, `stage: "fresh1/P0/smoke"`, `cap_usd: "0.10"`, and `exhaustion_policy: "pause"`. These exact fields must be filled from a reviewed, current account and billing snapshot; the runner does not create or approve the grant. The account ID and token are read only when an execution is attempted. Do not place the token in a grant, manifest, CLI argument or committed file. The initial smoke remains **unapproved** at this checkpoint, and no Cloudflare request was sent.

Before any hosted attempt, verify that the existing token has the required Workers AI scope, review the live price and billing plan, and allocate the Cloudflare cap in a reviewed grant. The first authorized smoke must verify the documented REST envelope and exact choice-answer shape; until then the [parser](../scripts/clef_native_preparation.py) is tested against fixtures, not a live Clef response. Cloudflare notes that long `state` input may be truncated to fit context, so the smoke must inspect that boundary too. The adapter does not use image input or generated-text output. A 60-record development phase needs a new reviewed stage, its own budget admission and a reviewed terminal smoke; this runner does not dispatch development requests.

Offline verification: `python3 -m unittest tests.test_clef_native_preparation tests.test_clef_native_smoke_runner -v` and `python3 scripts/clef_native_preparation.py`. The preparation CLI prints only a summary by default; `--output` can save an input-only manifest for review. The smoke runner's `--execute` path is deliberately gated by the reviewed grant, environment, billing hashes and separate ledger. The tests inject transport and perform no Cloudflare request.
