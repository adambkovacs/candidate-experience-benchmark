# Six Codex fresh matched-three series

Independent review approved this controller, and 16 combined offline tests passed. Root froze and reconstructed all 18 manifests on 28 September 2026. All six first P0 smoke tests completed and were inspected. Their six first P0 development phases have been dispatched; no full development phase is claimed complete at this checkpoint. The existing repeat controller and historical responses remain unchanged.

The six exact configurations are `codex-gpt-5.6-luna-xhigh`, `codex-gpt-6-astra-medium`, `codex-gpt-5.6-terra-low`, `codex-gpt-5.6-terra-medium`, `codex-gpt-6-sol-low-batch10` and `codex-gpt-6-luna-low-batch10`. Each writes to its own `-fresh-matched3` series. All old attempts, including failures, remain in their original folders. A failed output alone would not disqualify a first pass under the [repeat protocol](REPEATABILITY_PLAN.md). For the first four configurations, the [saved continuation reconciliations](../results/prompt-comparison-v1-2026-09-24/subscription-suffix-continuation-v1/reconciliation-v1/) show an interrupted ten-record position with unresolved outcome and later suffix timing. The historical condition is not one reconstructable, continuous 60-position pass. For the two low configurations, their [P0 source audits](../results/prompt-comparison-v1-2026-09-24/paired-reports/) identify missing original request, timeout and schema proof. The new first pass cannot be constructed by treating later responses as if they were original requests. These facts, rather than invalid or failed labels by themselves, motivate three new passes.

[`codex_fresh_roster.py`](../scripts/codex_fresh_roster.py) uses the frozen [`batch_prompt`, `batch_schema` and `parse_batch`](../scripts/codex_batch_benchmark.py), the [`Codex command and result parser`](../scripts/codex_benchmark.py), and input-only [`inputs.jsonl`](../data/pilot/inputs.jsonl). P0 has no parent ID. P1/P2 retain the **original** configuration ID in their prompt, never the new evidence-folder ID. The policy is the text before `## Simulated routing` in the [labeling guide](LABELING_GUIDE.md). No reference labels or prior predictions enter plan preparation or an inference request. A separate reporter may score closed evidence later.

Each configuration has three new passes: `fresh1` runs P0, P1, P2; `fresh2` runs P1, P2, P0; `fresh3` runs P2, P0, P1. Each condition sends one three-record smoke, then six fixed batches covering DEV-001 through DEV-060. That is nine smoke and nine development phases per configuration. A complete run across six configurations requires 54 smokes and 324 development batch requests. The controller pins `/opt/homebrew/bin/codex` and `codex-cli 0.156.1`, a 600-second request timeout, ChatGPT subscription login and the fixed CLI flags. It records the actual command and raw response. Seed, serving revision and hardware remain unavailable; batch elapsed time is a client duration, and any record-level share is amortized rather than an individual inference latency. The historical 0.155 clients remain observational and are not claimed equivalent to this new runtime.

Offline preparation, after review of this source, is one `prepare` invocation per configuration:

```sh
python3 scripts/codex_fresh_roster.py --config codex-gpt-6-astra-medium prepare
```

`prepare` exclusively writes `fresh1`, `fresh2` and `fresh3` manifests and refuses an existing evidence tree. Each manifest binds the controller and pure composer/parser sources, exact input/policy/bundle files, the historical exclusion evidence, request prompt/schema hashes and condition order. Review the three printed manifest hashes per configuration, then use the exact hash for every phase. `runtime-check` checks only CLI controls and subscription login; it makes no model request. The first admitted smoke is the model/effort capability test.

For each smoke or development phase, the operator must obtain a fresh Codex `get_usage_limits` result and create a phase-specific root-review JSON receipt outside this public repository in a mode-0700 directory, with mode-0600 file permissions. The receipt schema is `codex-fresh-roster-root-review-v1`. It must bind `approved:true`, `configuration_id`, `pass`, `condition`, `phase`, `manifest_sha256`, `controller_sha256`, `model`, `effort`, `runtime`, and `cli_path`. Its `quota` object must record `source:"Codex get_usage_limits"`, `checked_at_utc`, `ordinary_usage_allowed:true`, `spend_control_reached:false`, `credits_available:false`, `unlimited_credits:false`, `paid_overage_disabled:true`, a positive `weekly_remaining_percent`, and a positive `five_hour_remaining_percent` when that window is reported. The root reviewer must derive the credit fields from the observed `hasCredits:false`, `unlimited:false` and zero balance, and attest that paid overage remains disabled. Missing credit data cannot be treated as false. These are point-in-time reviewed observations, not proof that the provider cannot change account state after admission. The check expires after five minutes. A development receipt also binds `smoke_inspection_sha256`. Only the receipt's SHA-256 enters public admission evidence; account usage and private receipt paths stay outside the repository. No credit redemption or paid overage is authorized.

The admitted command takes `--config ID smoke`, followed by `--pass`, `--condition`, `--manifest-sha256`, `--review-receipt` and `--review-sha256`. After it completes, inspect the saved raw JSON, requested model and observed runtime controls, and three predictions; record a nonempty observation through the `inspect` action. The served model identity is unknown unless raw metadata actually exposes it. Development requires a new quota receipt bound to that inspection. Condition order and all preceding passes are enforced before a claim. The phase claim and request-start journal are durable before dispatch. A raw sidecar is fsynced before parsing. Known invalid or failed positions are retained, and a non-OK batch stops before the next one. An uncertain transport outcome stops with its started position unreplayed. No phase with an admission, claim or attempt can be implicitly restarted.

The [offline test](../tests/test_codex_fresh_roster.py) uses a fake backend to check normal smoke and development, exclusive no-replay, source drift, order, private quota rejection, CLI drift, raw-before-parse invalid retention and unknown transport stop. Running those tests does not create a manifest in the results tree or call the model.
