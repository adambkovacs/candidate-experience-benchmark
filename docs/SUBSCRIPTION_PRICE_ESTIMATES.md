# Subscription usage at public API rates

The site can show an API-equivalent estimate for saved Claude and Codex subscription runs. This is a way to compare token use at public prices. The actual subscription charge, overage, and quota consumed per request were not observed and stay unknown.

The offline builder is `python3 scripts/build_subscription_price_estimates.py`. It reads the existing public run and repeat reports, checks saved raw batch ledgers where available, and writes `public-site/subscription-price-estimates.json` and `public-evidence/subscription-pricing-v1/usage-aggregates.json`. It makes no model or billing request. The price JSON has `runs` keyed by the existing site run ID, `repeatPhases` keyed as `configuration:pass:condition`, and `repeatSeries` keyed by configuration. Each entry carries its exact model ID, measured token fields, public usage-projection path, rate source and check date, estimate status, and a null `actualSubscriptionChargeUsd`.

The public usage projection contains only model IDs, token totals, usage status, and SHA-256 bindings to the saved sources. It lets a reader reproduce the arithmetic without publishing private raw attempts, prompts, or account data. A hash binds the projection to a saved local source; it does not make that source publicly inspectable. Each projected entry also binds to the corresponding public aggregate report. In a clean checkout, the builder validates that report hash, exact model ID, reported token fields, and cache-write partition before using projected totals that were derived from private ledgers. The generated price feed is byte-for-byte reproducible from the committed public files. To refresh the projection after new saved evidence arrives, run `python3 scripts/build_subscription_price_estimates.py --refresh-provenance-from-local` only with the complete local evidence set.

The rate card uses the exact model IDs in the saved records. Rates are the public standard short-context API prices checked on 2 October 2026, from the [Claude model pages](https://platform.claude.com/docs/en/about-claude/pricing) and [OpenAI model pages](https://developers.openai.com/api/docs/pricing). Each model's direct pricing URL and all five rates are in the JSON. These prices are a current comparison basis; they do not claim to reconstruct past subscription billing or historical API prices.

Claude reports uncached input, cache reads, and cache writes separately. When the raw usage gives the write lifetime, the builder applies the corresponding 5-minute or 1-hour rate. Some older public aggregates omit that split or mix total input with uncached input. Those runs remain unpriced unless a matching raw ledger resolves the fields. OpenAI reports cached input within total input, so the builder subtracts cache reads and reported cache writes before pricing uncached input. If a component is missing, `estimateUsd` is null. Missing data is never treated as zero.

Reasoning tokens are a subset of output tokens in these CLI reports. The JSON shows their observed count for context and charges output only once. A partial run can have an estimate for its known usage, labelled `known_usage_only`; it is not a full-run estimate. `repeatSeries.fullSeriesEstimateUsd` is populated only when every phase has a complete estimate. A historical run can also be the `original` repeat phase; those entries describe the same use and must not be added together.

The generated feed currently contains 142 historical Claude/Codex runs and 369 repeat phases across 41 series. Of these, 122 historical runs and 364 repeat phases have a price estimate; 37 series have a complete nine-phase total. Five older Opus 5.5 phases lack the cache-write lifetime needed for this current-rate calculation. Their saved CLI list-price estimate is shown separately on the site. Other entries remain visible with a reason such as `cache_write_tokens_unreported`, `cache_write_duration_unknown`, or `missing_token_component`. Rebuild the feed after new saved usage arrives or the public rate snapshot changes.
