# Alex OpenJev 0.8B native P0 repeat admission

The proposed repeat study has three new P0 passes, `fresh1`, `fresh2`, and `fresh3`. The 23 September run remains historical observational evidence. Its [60 development rows](../results/alex-openjev08-mps-2026-09-23/development.jsonl) are ordered, valid, and have one recorded attempt each, but the exact runner revision that executed them was not recorded. A matching NLI input shape cannot establish that missing source-byte provenance, so the old run is not labeled pass 1.

The offline [admission controller](../scripts/alex_openjev08_repeat_admission.py) checked the saved smoke and development hashes (`ae414f56…` and `8a85a107…`), the pinned Alex artifact revision `f004f37e52695d6ddfb914a64dbf93942839ba1e`, and all ten local artifact files by content hash. It reconstructed all 60 records' 14 ordered premise/hypothesis inputs with the pinned tokenizer. Their full token lengths match the saved historical lengths and stay below the 4,096-token limit. The saved NLI probabilities also reproduce the recorded four-field predictions by maximum entailment. The shared saved `request_sha256` describes common request intent; it does not prove the historical NLI template or tokenizer bytes. The [earlier seven-configuration audit](ANYJEV_ALEX_OPENJEV_NATIVE_P0_NEXT_ADMISSION_2026-09-28.md) records the historical context.

The new plan binds the input-only 60 IDs and feedback hashes, policy prefix, source files, all ten artifact hashes, tokenizer IDs for every NLI input, the model template and NLI class order, historical evidence hashes, pinned Python package versions, hardware identity, and the ordered three-pass schedule. Native execution uses MPS float32, batch size 4, no quantization, no calibration, no truncation, and the same 14 hypotheses and max-entailment projection. It reads no reference labels. Local electricity and hardware costs are unknown, and recorded elapsed time is client prediction time rather than isolated model compute time.

Each fresh pass has a separate three-record smoke and 60-record development stage. The controller takes the shared native host lock, requires an exact reviewed stage receipt, and writes an exclusive claim before model load. It fsyncs `request_started` before prediction, saves raw NLI probabilities before projecting the answer, and then writes the record and terminal stage evidence. Development requires a completed, successful smoke plus a separate inspection and receipt. The next pass requires the previous pass's completed development evidence. A started request with missing raw output stays uncertain; the controller refuses stage replay and does not fill that position from a second attempt. A saved invalid NLI output is retained as invalid rather than repaired.

The [manifest](../results/repeatability-v1/alex-openjev08-native-p0-v1/manifest.json) was frozen and independently reverified offline at SHA-256 `6a4821b492030360535a4218302cbd82f4e04d4677eab92afa742d317c6627cf`. This is preparation, not live admission. No receipt has been issued, and the controller has not loaded weights or made an inference. Its seven focused [tests](../tests/test_alex_openjev08_repeat_admission.py) use fakes to exercise identity, ordering, raw-before-projection, interrupted attempts, and receipt gates. Before any live stage, root must review the frozen manifest and source hash, confirm the shared GPU is free, and issue a distinct receipt for that stage.
