# Public presentation review, 7 October 2026

## Design read and scope

Reading this as a public research report for recruiters, leaders and technical readers. It should feel like an evidence-led editorial report with modest interaction. The existing static site is the implementation surface. This review proposes a presentation change; it does not change benchmark data, model categories or the published site.

The current page already explains the 60 fictional comments and four decisions, links to saved runs, and includes a run ranking, validity-versus-agreement plot, prompt comparisons and repeatability views ([site source](../public-site/index.html), [category rules](../public-site/model-categories.js), [outcome chart](../public-site/outcome-chart.js)). Its first ranking filters by prompt and route, while dedicated decision models and general LLMs share one ranking. The later scatter can filter categories. A reader therefore meets a mixed league table before getting a clear cohort choice. Scores also represent runs with different prompts, routes and interfaces. The current page says so, but the structure gives the ranking more prominence than that qualification.

## Proposed page flow

1. **Opening question.** Keep the current candidate example and four decisions. Then add a three-way cohort chooser: **Decision models**, **General-purpose LLMs**, **All models**. Explain that the first two give a focused view while the third is exploratory across different interfaces. The category taxonomy already exists in `model-categories.js`; the chooser should drive a shared state rather than introduce a second classification system. If a model belongs to multiple categories, show that explicitly and avoid double-counting it in cohort totals.
2. **First exhibit: validity and agreement.** Lead with the existing two-axis plot, filtered by the chosen cohort and one prompt condition. Keep both axes out of 60, show exact counts in text, and link selected points to the run. A plot of 60/60 valid and 45/60 all-four matches illustrates why usable format and agreement are separate. Group coincident points with an accessible chooser as the existing plot already does. Use a short answer-first heading such as "A usable answer can still disagree with the reference."
3. **Second exhibit: prompt changes.** In a selected, comparable group, show paired gains, losses and unchanged reviews for P0→P1 and P1→P2. The chart should state the shared-valid denominator as well as the full-run 60 denominator. Keep Jev/other native Choice instruction changes in their own comparison lane, and mark interrupted or descriptive comparisons distinctly. A click reveals the changed reviews and both saved answers.
4. **Third exhibit: repeatability.** Plot the three saved passes as connected points or small multiples for a single configuration and prompt. Annotate incomplete cells rather than interpolating them. Beside score range, show the count of reviews whose labels flipped: equal totals can conceal different decisions. Link each point to its exact pass and evidence.
5. **Detailed comparison.** Keep the existing full explorer, category and interface filters, run IDs, costs and sources. Move it below the three exhibits. Preserve deep links such as `?run=...#inspect`, existing downloadable feeds and method details.

## Interaction contract

- A single cohort selection persists across the first plot and detailed comparison; the prompt selector persists where it is meaningful. Each exhibit states the active cohort, prompt and number of complete versus partial runs.
- Selecting a chart point focuses the matching run row and exposes the exact run ID, route, interface, validity, four-field agreement, source link and status. Selecting a changed review opens its existing review detail. URL query or hash state should make those views shareable.
- Controls work with keyboard and touch. Every plot has a text or table equivalent, clear focus, and a no-match message. Do not rely on color alone for model category or result state. Motion is optional and respects reduced-motion settings.
- Use restrained type, spacing, axes and annotations. No 3D, hologram, animated background, sound, or decorative motion around measured numbers. A plain chart that is easy to read at 390 px has priority over a dense interactive canvas.

## Editorial and methodological guardrails

Use "matched the provisional reference" for agreement, not "accuracy" or "best model." Show 60 synthetic comments, human-checked but disputed references, and the exact scope of each comparison beside the visualization. A run with 59 valid answers remains out of 60 for its full-run score; a paired chart must separately disclose its shared-valid count. Distinguish request time from pure inference time, estimated from observed cost, and missing cost data. Do not aggregate unlike routes, prompts or repeated evaluations into an apparently controlled model ranking. A label flip matters even if the score is unchanged.

The bounded implementation is a redesign of the first results passage and reuse of existing feeds and detail panels. It needs no framework migration, new model calls or benchmark-data edits. The main cost is careful shared filter state and verification that every plotted mark resolves to the exact saved source. The main risk is that cross-category comparison appears causal or definitive; the cohort labels, scope notes and evidence drill-down should prevent that reading.
