# Clef connected-app smoke handoff

The direct `CF_API_TOKEN` Workers AI model-list request returned HTTP 403 on 2 October 2026. The connected Cloudflare app listed both Clef routes, so the initial $0.10 Clef smoke can use that app after a separate bridge review. This bridge changes the execution surface. It does not prove that the direct token has Workers AI permission, and it does not authorize a larger stage.

The [bridge](../scripts/clef_connected_app_bridge.py) calls the frozen [smoke runner](../scripts/clef_native_smoke_runner.py) with an injected transport. The runner checks its exact input manifest, reviewed $0.10 grant, account hash, billing-source hashes, and locked Cloudflare ledger. It durably reserves a full-context amount and writes `started` before the bridge publishes a ready request. For each model, only `fresh1/P0/smoke` DEV-001–003 can be sent. A missing or malformed connected-app reply stops the stage as `unknown_outcome`; the held reservation stays in the ledger and the request must not be replayed.

An independent bridge review receipt is required in addition to the smoke grant. Its exact fields are `kind: clef-connected-app-bridge-review-v1`, `approved: true`, `reviewer`, `transport: mcp__codex_apps__cloudflare_execute`, `model`, `stage: fresh1/P0/smoke`, `manifest_sha256`, `grant_sha256`, `runner_sha256`, `bridge_sha256`, `account_id_sha256`, and integer `wait_seconds` from 1 to 600. The reviewer must verify that the connected app account matches the account hash in the grant and that the app can call the exact selected route. A direct-token HTTP 403 could reflect an account mismatch, so the review cannot infer the account from the token name. The bridge checks each receipt field before the runner can reserve or emit a request.

After review, the operator starts one model with `python3 scripts/clef_connected_app_bridge.py run --execute --model clef --manifest results/clef-native-v1/preparation.json --grant <reviewed-grant.json> --review <bridge-review.json> --env-file <private-env-file> --wait-seconds 300`. Use `clef-flash` and a separate model-specific bridge review for Flash. The command waits for each response. The ready file appears at `results/clef-native-v1/<model>/fresh1/P0/smoke/app-bridge/<attempt-id>.request.json`. It contains the exact synthetic request body, a request hash, the route with an `{ACCOUNT_ID}` placeholder, and an account ID hash. It contains no bearer token or account ID.

For each ready file, the parent operator uses the connected Cloudflare app's `mcp__codex_apps__cloudflare_execute` tool. Its documented `cloudflare.request()` accepts `method: "POST"`, `path`, and `body`; the [Cloudflare REST route](https://developers.cloudflare.com/workers-ai/get-started/rest-api/) is `/accounts/{ACCOUNT_ID}/ai/run/{MODEL_ROUTE}`. Use the account already verified for the bridge review, replace the placeholder in the ready path, and pass the ready `body` without changing its fields. Save the returned `cloudflare.request()` object exactly as JSON, including `status`, `success`, `errors`, `messages`, and `result`, in a private app-result file. This object is a connector-normalized result; preserve the complete outer tool return separately when available. If the tool errors, times out, or its send status is uncertain, submit no result and allow the bridge timeout to record an unknown outcome. There is no retry.

Submit a verified app result with `python3 scripts/clef_connected_app_bridge.py submit --request <ready-request.json> --app-result-file <saved-app-result.json>`. The submit command derives the HTTP status from the app result, checks the required Cloudflare response fields, and publishes an immutable response file atomically. The runner then stores the serialized connector result in `raw.jsonl` and applies its strict REST parser. These are the exact saved connector-result bytes, **not captured HTTP wire bytes**. A second submit for the same attempt fails, and a response that arrives after the timeout is evidence only; it never reopens or replays the stopped stage.

Cloudflare's [Clef](https://developers.cloudflare.com/workers-ai/models/clef/) and [Clef Flash](https://developers.cloudflare.com/workers-ai/models/clef-flash/) pages identify the two pinned routes and input prices; those model-page bytes are the billing sources checked by the original grant. The [pricing page](https://developers.cloudflare.com/workers-ai/platform/pricing/) provides a separate published cross-check. The combined six-request full-context reservation is $0.064884 against the separately approved $0.10 Cloudflare cap. The two models have separate smoke directories but share one locked ledger; later development runs require a new review and admission.

Offline check: `python3 -m unittest tests.test_clef_connected_app_bridge tests.test_clef_native_smoke_runner -v`. It tests reserve-before-ready, app-error stop, unknown-outcome timeout, no replay, exact receipt binding, and atomic handoff without a Cloudflare call.
