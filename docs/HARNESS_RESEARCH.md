# Evaluation framework research

Status: source review on 2026-09-24. This is a selection recommendation, not a completed integration test. This review made no model calls, downloaded no weights or datasets, and started no paid services.

## Recommendation

Accepted project direction, 2026-09-24: finish the current benchmark without changing frameworks mid-run. Preserve the existing adapters and evidence, then consolidate orchestration around our requirements. Framework adoption is an outcome of an offline comparison, not a prerequisite. Keep the current benchmark scope, model roster and completion requirements unchanged. The [architecture decision](HARNESS_SPEC.md#architecture-decision) defines this direction.

Test [Inspect AI](https://inspect.aisi.org.uk/) and [promptfoo](https://www.promptfoo.dev/) with the same small, offline adapter fixture. Inspect is the first external candidate to test for a Python implementation: its [custom ModelAPI](https://inspect.aisi.org.uk/extensions-model-api.html) can return a raw request and response with a model result, and its [eval sets](https://inspect.aisi.org.uk/eval-sets.html) offer resume and parallel task execution. Promptfoo is the challenger for prompt and model matrices: it supports [Python providers](https://www.promptfoo.dev/docs/providers/python/), [custom scripts](https://www.promptfoo.dev/docs/providers/custom-script/), [resume, concurrency and JSON/JSONL export](https://www.promptfoo.dev/docs/usage/command-line/). Both core repositories have an [MIT license for Inspect](https://github.com/UKGovernmentBEIS/inspect_ai/blob/main/LICENSE) and an [MIT license for promptfoo](https://github.com/promptfoo/promptfoo/blob/main/LICENSE). GitHub's repository API showed both as public and unarchived on the review date.

Compare both with the consolidated project approach. Adopt a framework or individual component only where an integration test proves protocol fidelity and a measurable reduction in maintenance and operator effort. Record custom code, workarounds, dependency and upgrade burden, manual launches, monitoring interventions, recovery steps and commands for the same fixtures. Retaining the project coordinator is a valid outcome; avoid a full rewrite or duplicating suitable library features. The project-owned coordinator in [HARNESS_SPEC.md](HARNESS_SPEC.md) still needs to own the experiment plan, label-free request capsules, a single atomic $10 OpenRouter reservation ledger including prior spend, immutable attempt artifacts, recovery decisions, local GPU locks, and final-denominator reporting. This is an architectural inference from the required evidence and money controls, not a claim that either framework is deficient at all evaluation work.

The decisive spike has five fixture cases: a ten-record prompt with a fixed P1/P2 membership order; a simulated 429 followed by success; a crash after dispatch but before response persistence; an invalid JSON model response; and a specialist adapter whose output is a native choice/probability decision. Compare the exact rendered request bytes, all attempts and charges, reference isolation, restart behavior and exported rows. Use saved responses and simulated failures only: no live model requests, benchmark reruns or spending. Bound the comparison to these five cases and the two named external candidates before deciding whether further investigation is justified. Reject a framework as the execution owner if it cannot pass without a fork or broad monkey-patching; its reporting or development views may still be adopted if they demonstrate a separate benefit. Success means the next experiment runs from one configuration and one command, recovers predictably, and explains every result without an expensive LLM supervising each step.

## What the primary candidates actually provide

| Candidate | Verified useful feature | Boundary to test before adoption |
| --- | --- | --- |
| Inspect AI | [ModelAPI extensions](https://inspect.aisi.org.uk/extensions-model-api.html), [task/eval-set resume](https://inspect.aisi.org.uk/eval-sets.html), [full raw API logging with a flag](https://inspect.aisi.org.uk/eval-logs.html), [provider concurrency controls](https://inspect.aisi.org.uk/models-concurrency.html). [MIT source](https://github.com/UKGovernmentBEIS/inspect_ai/blob/main/LICENSE); PyPI listed 0.3.268 on 2026-09-22 in its [release history](https://pypi.org/project/inspect-ai/0.3.268/). | [Recoverable model API errors retry indefinitely by default](https://inspect.aisi.org.uk/models-concurrency.html); underlying SDKs may retry too. Eval sets retry failed tasks and normally [clean up failed logs](https://inspect.aisi.org.uk/eval-sets.html). Preserve every attempt outside these views, set finite retries, and test disablement of SDK retries. Inspect notes that eval-set task identity [does not include base_url](https://inspect.aisi.org.uk/models.html), so route identity must be recorded in the project plan. |
| promptfoo | [Prompt/configuration matrix](https://www.promptfoo.dev/docs/configuration/reference/), [Python provider](https://www.promptfoo.dev/docs/providers/python/), [resume and JSONL export](https://www.promptfoo.dev/docs/usage/command-line/). [MIT source](https://github.com/promptfoo/promptfoo/blob/main/LICENSE); GitHub listed 0.123.1 on 2026-09-18 in [releases](https://github.com/promptfoo/promptfoo/releases). | [Disk response cache is on by default](https://www.promptfoo.dev/docs/configuration/caching/); set no-cache and prove it for repeats. Built-in 429 backoff and [retry-errors](https://www.promptfoo.dev/docs/usage/command-line/) can change the attempt history; retry-errors removes a prior error after success in its result view. Custom provider context includes test variables and metadata, so pass only label-free data and score in another process. |

Neither candidate's published feature list establishes an atomic cap across simultaneous OpenRouter workers, reconciliation of an ambiguous billable dispatch, or complete isolation of local CLI workspaces. The spike should decide whether the coordinator calls the framework for each admitted unit, or calls existing workers and imports outputs for analysis. Do not infer these properties from a successful demo.

## Provider and hosted platform options

OpenAI's hosted [Evals platform is deprecated](https://developers.openai.com/api/docs/deprecations): existing evals become read-only on 2026-10-31 and its dashboard/API are scheduled to shut down on 2026-11-30. This notice concerns the hosted product; the separately listed [OpenAI Evals source repository](https://github.com/openai/evals) remains accessible at the review date. OpenAI's [Datasets](https://developers.openai.com/api/docs/guides/evaluation-getting-started) serve prompt experimentation, and promptfoo remains a local, MIT-licensed option. Anthropic's [console evaluation tool](https://docs.anthropic.com/en/docs/test-and-evaluate/eval-tool) compares prompt versions. Google's [Vertex AI Gen AI evaluation service](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/eval-python-sdk/view-evaluation) can compute metrics on datasets. Those hosted facilities do not replace subscription CLI execution or one project-owned run ledger across all providers.

Cloudflare [AI Gateway Evaluations are deprecated for new accounts](https://developers.cloudflare.com/ai-gateway/evaluations/). Its gateway remains a routing and logging service, with [optional retries and caching](https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/), not a replacement for the evaluator. Vercel AI Gateway provides [provider routing](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options) and [budgets](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets), but its own documentation calls those budgets soft: a crossing request can exceed the cap, and bring-your-own-key spend is excluded. Neither hosted gateway proves the strict shared OpenRouter cap.

OpenRouter already supplies the approved non-GPT/Claude hosted route. Its [model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks) may switch the served model after errors, including rate limits and moderation. The benchmark must pin an approved model and provider route, disable unwanted fallbacks, and verify the returned identity. This is a gateway policy, not an evaluation framework feature.

The Chinese-lab/open-model side is represented by EvalScope and OpenCompass, rather than a claim that DeepSeek or Qwen operates a general cross-provider benchmark service. Hugging Face Lighteval is the local/open-model counterpart. These choices are source-supported and reusable, but each would need adaptation to the benchmark's custom labels and subscription/native execution surfaces.

## Selection and versioning rule

The versions above are evidence of recent maintenance, not recommended dependency pins. At the implementation spike, install exact immutable versions in a clean environment; save the dependency lock, source URL, license texts and hashes; then run the five fixture cases and a no-network offline export/scoring check. A new version must rerun these gates before use in a frozen experiment. The research did not inspect every transitive dependency, run candidate code, verify live account entitlements, or prove any framework's final adapter behavior.
