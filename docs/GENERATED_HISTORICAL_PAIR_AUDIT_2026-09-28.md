# Historical generated prompt pairs: eligibility audit

Status on 2026-09-28: **none of these three historical P0/P1/P2 sets qualifies for a strict audited paired report**. Each set accounts for the same 60 development IDs in each condition, but record coverage alone does not establish that the only changed control was the prompt instruction. This audit made no model requests and did not alter the saved results. The [machine-readable audit](../results/prompt-comparison-v1-2026-09-24/paired-reports/generated-historical-audit-v1/eligibility-audit.json) binds the nine record files, supporting stage evidence, inputs, provisional references and source versions by SHA-256.

| --- | ---: | ---: | ---: | --- |
| `openjev-generated-off` | 52 / 8 | 54 / 6 | 56 / 4 | Not established: P0 lacks saved wire body and server-rendered token IDs. |
| `openjev-generated-on` | 59 / 1 | 50 / 10 | 53 / 7 | Not established for the same P0 gap; requested thinking-on is not evidence of effective reasoning. |
| `anyjev-qwen06-generated-control` | 0 / 60 | 0 / 60 | 30 / 30 | Not established: P0 lacks saved messages and rendered-prompt identity. |

These are **valid output / intrinsic invalid output** counts, not scores against the reference. All 540 saved records have unique DEV-001–DEV-060 membership in order within their condition. Invalid outcomes and their raw responses remain in the [OpenJev off P0](../results/openjev-local-generated-off-2026-09-23/development.jsonl), [OpenJev on P0](../results/openjev-local-generated-on-2026-09-23/development.jsonl), [AnyJev P0](../results/anyjev-qwen06-generated-mps-2026-09-23/development.jsonl) and the P1/P2 files linked below. No failed answer was repaired to obtain these counts.

The two OpenJev P0 files save canonical request hashes, raw responses, usage and requested generation settings. A read-only reconstruction with the current [`make_payload`](../scripts/jev_benchmark.py) reproduces the saved P0 request hash for all 60 IDs in each mode. That check does **not** prove the historical executing source bytes, HTTP wire body or server-rendered token IDs. The later [off P1](../results/prompt-comparison-v1-2026-09-24/openjev-generated-exact-v1/generated-off/P1-development.jsonl), [off P2](../results/prompt-comparison-v1-2026-09-24/openjev-generated-exact-v1/generated-off/P2-development.jsonl), [on P1](../results/prompt-comparison-v1-2026-09-24/openjev-generated-exact-v1/generated-on/P1-development.jsonl) and [on P2](../results/prompt-comparison-v1-2026-09-24/openjev-generated-exact-v1/generated-on/P2-development.jsonl) files save wire-body text/hash and rendered token-ID hash for every development row, with separate terminal and inspection evidence. They cannot supply the missing P0 observations retroactively. The saved `enable_thinking:true` for the on route is a requested setting; [the admission audit](GENERATED_SPECIALIST_REPEAT_NEXT_ADMISSION_2026-09-28.md) notes that effective thinking remains unverified.

AnyJev P0 saves request hashes, raw generations, finish reasons and token counts. Current pure [`control_messages`](../scripts/anyjev_generation_control.py) reproduces all 60 P0 request hashes, but the historical rows do not save the messages, chat-template rendering or generated token IDs. [P1](../results/prompt-comparison-v1-2026-09-24/anyjev-generated-exact/P1-development.jsonl) and [P2](../results/prompt-comparison-v1-2026-09-24/anyjev-generated-exact/P2-development.jsonl) save messages, rendered-prompt hashes, generated token IDs and stage evidence. Shared model ID, MPS BF16 settings and record count cannot substitute for the absent P0 prompt evidence. The 60 invalid P0 outputs and 60 invalid P1 outputs remain observations, not missing calls.

The central [paired evaluator](../scripts/evaluate_prompt_variants.py) has extractors for OpenRouter, LM Studio SDK, Claude batch and Codex batch evidence, but none for these local generated routes. Its `declared_only` path sets controls verification to unavailable and cannot yield an eligible pair. Accordingly this audit publishes **no `prompt-pairs-v1` manifest and no paired evaluation**. A manifest populated with declarations would give a false impression of request verification. The [generated specialist admission audit](GENERATED_SPECIALIST_REPEAT_NEXT_ADMISSION_2026-09-28.md) already specifies the next clean route: three newly matched P0/P1/P2 passes with frozen prompt bytes, rendered tokens, parser, model/runtime controls, inspected smokes and terminal evidence. This historical audit neither authorizes those runs nor replaces their admission review.

References are [provisional AI-reviewed development labels](../data/pilot/proposed_labels.jsonl). The reference file was hash-bound but its labels were not used to decide eligibility or sent to a model. Any future descriptive score comparison should keep invalid outputs in the denominator of 60, distinguish observed controls from reconstructed ones, and avoid a causal prompt-effect claim from these historical files.
