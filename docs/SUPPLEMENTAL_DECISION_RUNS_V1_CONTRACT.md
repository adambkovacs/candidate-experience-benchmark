# Supplemental decision runs: integration contract

The [feed](../public-site/supplemental-decision-runs-v1.json) adds 21 closed development runs to the main explorer: Solar Decide fresh1/P0–P2, Liquid d1 fresh1–3/P0–P2 and Tev1-4B fresh1–3/P0–P2. Its [builder](../scripts/build_supplemental_decision_runs_v1.py) checks each published report against its existing source-bound reporter, verifies the public projection hashes and refuses an ID collision with the historical [explorer data](../public-site/data-provider-errors-v1.json). Rebuild with `python3 scripts/build_supplemental_decision_runs_v1.py write`; verify without changing files with `python3 scripts/build_supplemental_decision_runs_v1.py check`.

`app.js` may load the file as an optional source. Accept it only when `schema` is `supplemental-decision-runs-v1`, `denominator` is 60, all 21 IDs are unique and absent from the base feed, and every row has a valid `P0`/`P1`/`P2` condition, 60 records, 60 valid answers, five integer metrics from 0 to 60, and the expected public source links. Reject the entire supplemental file if any row fails; keep the base explorer available. Append the validated rows before building model, experiment, filter and overview controls, and before emitting `benchmark:saved-runs-ready`. The feed does not add cases or prompt-comparison objects.

Each P1/P2 row's `parentBaselineId` points to P0 in the same named pass. `repeatPass`, `model`, `returnedModel`, `provider`, `interface`, `condition` and `protocolId` retain the distinct model and route. `complete:true` means a closed 60-position development run, not that Solar has finished its nine-pass plan. The Solar rows are first-pass only. Liquid and Tev each have nine closed runs. All three use native four-question Choice, so explorer labels should say native choices, not generated chat answers. Extend `model-categories.js` and the main family filter for the three exact model IDs before presenting category-specific filtering; otherwise these rows fall under “unknown” and “Other.”

`sourceOnlyDetails:true` is deliberate. `sourceRecordsUrl` links to Git-tracked public projections containing the 60 predictions for that row; the Solar and Tev projection files contain several stages, and Liquid links a single-stage file. `sourceRecordSha256` is the hash of the linked file; `evidenceUrl` links the aggregate report. No feedback text, private raw response, or individual `cases` entry is created by this feed. The existing individual-comments panel should keep saying that it has not loaded predictions, then link the public projection. An aggregate score must not appear as a fabricated review card.

`cost.knownUsd` is the report's provider-usage-derived development charge. `actualUsd` and `estimatedUsd` are null, and smoke charges are excluded. Do not relabel this as an invoice total or an API-equivalent subscription estimate. Token totals cover 60 provider-reported development requests; unsupported token categories are null, not zero. No public per-request client durations or server inference durations are available for these runs: `timing.requests` is zero and duration fields are null. The detail view should show timing unavailable. Generic subscription-cost copy in `app.js` should be scoped away from OpenRouter native-choice rows.

The [Solar report](../public-site/solar-decide-first-pass-findings.json), [Liquid report](../public-site/liquid-d1-native-full-findings.json) and [Tev report](../public-site/tev-native-full-findings.json) contain the paired and repeat findings. This feed supplies selectable run summaries, not new causal or calibrated-confidence claims. The [focused tests](../tests/test_build_supplemental_decision_runs_v1.py) check exact run coverage, source links, cost scope and rejection of changed public evidence.
