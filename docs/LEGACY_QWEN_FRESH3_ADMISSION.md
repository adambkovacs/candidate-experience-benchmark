# Six small-Qwen fresh repeat series

The [controller](../scripts/legacy_qwen_repeat_admission.cjs) prepares three fresh P0/P1/P2 passes for six historical configurations: Qwen3 0.6B HTTP nonthinking; Qwen3 0.6B SDK thinking on/off; Qwen3 1.7B SDK thinking on/off; and Qwen3.5 4B SDK thinking on. The planned total is 54 full development runs, separate from the existing five-model small-local matrix. Historical attempts are not counted as pass one. The unknown historical Qwen3.5 P2 DEV-019 remains untouched.

The [dated route audit](../results/route-audits/legacy-six-local-20260929/README.md) found no exact hosted family. The controller also checks the public catalogue before local dispatch and refreshes the check within five minutes. It preserves the distinct HTTP schema/512-token route and SDK template/4096-token routes. Every selected input must match its frozen rendered prompt, observed token count and context reserve before the phase claim and again before its request. The HTTP route also requires observed nonthinking initialization for the current loaded instance.

The pinned SDK exposes no public per-request configuration argument on its rendering method. The controller uses its actual configuration conversion and temporarily supplies the same override stack used by inference, restoring the original stack in a finally block. A regression compares this rendering stack with the actual pinned SDK respond path without sending inference.

Review verdict for offline preparation: **APPROVE** after the source review and 19 passing targeted tests. **RESIDUAL:** end-to-end parity with the loaded LM Studio backend remains unverified; missing or mismatched render, token, artifact, runtime or thinking evidence prevents dispatch. The common GPU lock keeps this work separate from Alex and other native runs. No local Qwen inference was launched during preparation.

A durable claim prevents replay. Initialization failures with no request-start or output evidence can be sealed as a documented no-send failure; this does not authorize replay of any started request. Each development phase requires a separate root-reviewed receipt and a successful inspected three-record smoke. Invalid and failed outcomes stay visible. The Qwen0.6 SDK nonthinking smoke may fail intrinsically, as historical results did; prompts and parsers must not be changed to conceal that result.
