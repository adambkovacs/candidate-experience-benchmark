## Part A — What a "decision model" is, and why now

### A1. Typed decisions vs. free-text generation

A decision model takes a **state** (the text or JSON you want judged) plus one or more **typed questions**, and returns a typed value with a probability distribution, in one forward pass, with no generated text to parse. TypeSafe's definition: "System One models are built to make fast, structured decisions that software can use directly," contrasted with LLMs, which "are designed to produce text for humans to read," so getting a judgment out of them means coercing and parsing text ([docs.typesafe.ai/introduction](https://docs.typesafe.ai/introduction)).

The three question primitives, now copied almost verbatim by every follower:

| Primitive | Question shape | Returns (Jev) | Source |
|---|---|---|---|
| **Noul** | "Is this statement true?" | `noul`: probability of yes, 0 to 1 | [primitives/noul](https://docs.typesafe.ai/primitives/noul) |
| **Choice** | "Pick one option from this list" (max 255 options) | `choice` (argmax), `probabilities` (map summing to 1), `confidence` | [api.md](https://docs.typesafe.ai/api.md) |
| **Score** | "Rate on this ordered rubric" (2 to 10 levels) | `score` (probability-weighted, can fall between levels), `legend`, `probabilities`, `confidence` | [api.md](https://docs.typesafe.ai/api.md) |

Key mechanical properties, as documented by TypeSafe:

- **No output tokens.** "No text generation, no parsing." Output tokens are free; billing is per input token ([models.md](https://docs.typesafe.ai/models.md)).
- **Fan-out.** All questions in a request are evaluated "in parallel, in isolation, against the same state," so adding questions barely changes response time ([introduction](https://docs.typesafe.ai/introduction)). TypeSafe's own cookbook measured 13 questions batched in one call at $0.000497 and 0.27 s versus $0.006090 and 2.71 s for 13 sequential single-question calls on jev-1.12 ([cookbooks/parallel_questions](https://docs.typesafe.ai/cookbooks/parallel_questions.md)).
- **Schema cannot be violated.** The answer is one of the supplied options by construction. TypeSafe says type errors are "mathematically impossible" ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Note that this guarantees *shape*, not *correctness*.
- **Confidence is a statistic, not a separate output.** For Choice, `confidence = (p_max − 1/n) / (1 − 1/n)`; it is 1 when all mass is on one option and 0 when spread evenly. For Score it also accounts for distance between levels. Noul answers have no confidence field. TypeSafe makes **no calibration promise** on that page: "The correct threshold values depend on your domain and the performance of the model for your use case ... Start with conservative thresholds, test with your own data" ([confidence](https://docs.typesafe.ai/confidence)).
- **Calibration is a population property.** "Calibration is measured across groups of predictions; it does not guarantee that an individual answer is correct" ([concepts/system-one](https://docs.typesafe.ai/concepts/system-one)).

### A2. Abstain / insufficient information: not a first-class primitive anywhere

None of the hosted APIs I checked ship a built-in abstain. The documented pattern is to **add an explicit fallback option yourself** and **threshold on confidence**:

- TypeSafe: the confidence page suggests high / medium / low bands (act, confirm, route to human) and example code with a 0.5 floor and a 0.9 bar for destructive actions ([confidence](https://docs.typesafe.ai/confidence)). The cookbooks add an "uncertain" outcome to Choice questions and send uncertain Nouls to human review ([cookbooks index](https://docs.typesafe.ai/cookbooks.md)).
- OpenAI: "include one [fallback choice such as 'other'] when your categories don't cover every possible input"; answers can also come back as `type: "refusal"`, with no documentation of when ([OpenAI Decisions guide](https://developers.openai.com/api/docs/guides/decisions)).
- Nimble: "Abstention is not built in. The README suggests adding a 'no match' option" ([bespokelabsai/nimble](https://github.com/bespokelabsai/nimble)).
- Strands Decider: no abstain; "confirm or ask a person when confidence is below 0.9" ([strands-labs/strands-decider](https://github.com/strands-labs/strands-decider)).
- Kev tests "unanswerable" items explicitly: Kev-4B emits 0.00 of them at p ≥ 0.9 versus Jev's 0.09 on one panel ([jaredpalmer/kev-4b](https://huggingface.co/jaredpalmer/kev-4b)).
- Span-01 is the exception by design: its output vocabulary is `present / absent / not_observable` ([Respan: Introducing Span-01](https://www.respan.ai/blog/introducing-span-1)).

This matters for the talk: "insufficient information" and "off-topic" are **your** labels to add, and the model will still spread probability over whatever options you gave it.

### A3. The "System 1" framing and Kahneman

TypeSafe: "The System One name comes from the concept Daniel Kahneman popularized in his book Thinking, Fast and Slow ... System 1 thinking is fast and intuitive. System 2 is slower and more deliberate," with emphasis on "fast, focused judgments" ([concepts/system-one](https://docs.typesafe.ai/concepts/system-one)). Kahneman (2011) characterises System 1 as "fast, automatic, frequent, emotional, stereotypic, unconscious" and System 2 as "slow, effortful, infrequent, logical, calculating, conscious" ([Wikipedia: Thinking, Fast and Slow](https://en.wikipedia.org/wiki/Thinking,_Fast_and_Slow)).

What TypeSafe says Jev is **for**: classification, routing, scoring, extraction, branching, map-reduce over large data, real-time applications, verification and guardrails ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). What it is **not for**: "System One models do not write replies, produce code, or generate explanations of their reasoning" ([concepts/system-one](https://docs.typesafe.ai/concepts/system-one)); "It does not generate text, write code, or hold a conversation ... Jev is not a drop-in replacement for the LLM behind Claude Code" ([introduction/coding-agents](https://docs.typesafe.ai/introduction/coding-agents.md)); text only, no images, audio or video ([models.md](https://docs.typesafe.ai/models.md)).

Mapping decision types to the two systems, grounded in TypeSafe's own published failure list for jev-1.13 (last reviewed 2026-10-02, [model-jaggedness/jev-1.13](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)):

| Suits System 1 (decision model) | Needs System 2 (reasoning LLM, or code) | Why (source) |
|---|---|---|
| Bounded label vocabulary, clear rubric, one factor per question | Compound judgments weighing several factors in one prompt | TypeSafe: decompose; "combining several judgments in one question" is a listed anti-pattern ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md), [introduction](https://docs.typesafe.ai/introduction)) |
| High volume, latency-sensitive, same state many questions | Anything needing an explanation or a written reply | Models "do not write replies ... or generate explanations" ([system-one](https://docs.typesafe.ai/concepts/system-one)) |
| Literal, surface-level reads of the state | Reading intent behind the words, negations, implied conditions | "Literal reading" is failure mode #1 ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)) |
| Judgments where code can pre-compute the facts | Arithmetic, counting, date ordering, duration checks | "The model is not a calculator"; dates "are read as text" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)) |
| Single-hop questions | Double negatives, properties of properties, multi-hop reasoning | "Indirection" reduces accuracy ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)) |
| Trimmed state that contains only what the question needs | Large states with irrelevant detail | Accuracy "falls as unrelated content grows" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)) |
| Trusted input | Adversarial or injected input | "The model does not treat state as hostile by default" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)); AlexWortega/openjev reports one adversarial line cut accuracy on 150 items from 0.833 to 0.467 ([model card](https://huggingface.co/AlexWortega/openjev)) |
| Options you have deliberately ordered and tested | Option lists where order is arbitrary and untested | "The model leans toward the first option" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)); AnyJev measured a 0.230 flip rate when options are reversed on raw Qwen3-8B ([AnyJev README](https://github.com/nokia-applied-research/AnyJev)) |
| Insufficient information / off-topic, **only if** you add that label and threshold on confidence | Insufficient information where the honest answer is a question back to the user | No abstain primitive exists (A2) |

### A4. Why now

Three things lined up in September 2026:

1. **A proof point with distribution.** Jev launched 2026-09-15 ([TypeSafe launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)) and within 24 hours "nearly 13% of paid teams" on Vercel AI Gateway were using it, "2x the GPT-5.6 family and over 6x Fable 5.1" ([Vercel blog, 2026-09-18](https://vercel.com/blog/ai-gateway-jev-model-launch)).
2. **A trivially copyable recipe.** Every open follower is a frozen Qwen or Gemma backbone plus a small head or LoRA that scores option logits in one prefill pass (Clef: "rank-256 low-rank adapters and a routing head ... a prefill-only pass scores the valid schema choices in parallel," [Cloudflare](https://blog.cloudflare.com/clef-decision-models/); Strands: "discard its language-modelling head," ~1M-parameter pointer head, rank-16 LoRA, [strands-decider](https://github.com/strands-labs/strands-decider); Nimble: LoRA on Qwen3.5-9B, 2,676 training pairs, one epoch, [nimble](https://github.com/bespokelabsai/nimble); Together's Tev1 trained for "$17," [togethercomputer/tev1](https://github.com/togethercomputer/tev1)). Training-free wrappers (AnyJev, SemIf) need no training at all.
3. **A shared wire format.** `POST /v1/systemone` with `state` + `questions` of type `noul | choice | score` is now implemented by TypeSafe, Cloudflare, Liquid, Upstage, Ollama, Kev, Strands, OpenJev and others (sources per model below), so switching models is a base-URL change. OpenAI and Perplexity use `/v1/decisions` with the same three types under different names.

## Part B — The landscape, one section per model

### B1. TypeSafe **Jev** (jev-1.13.0) — the origin

- **Maker / launch:** TypeSafe AI, San Francisco. Launched 2026-09-15 in early access ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Secondary coverage reports a $40M seed led by DCVC on the same day and CEO Diogo Almeida (ex-OpenAI, RLHF co-inventor) ([VKTR](https://www.vktr.com/ai-platforms/chatgpt-cocreator-launches-typesafe-ai-with-jev/), [YourStory](https://yourstory.com/ai-story/what-is-jev-typesafe-ai-decision-model)); **funding and valuation UNVERIFIED** from a primary source. Homepage still says "early access" on 2026-10-08 ([typesafe.ai](https://typesafe.ai/)).
- **What it is:** Proprietary, hosted only. "A new architecture"; no parameter count, no weights, no technical paper. Trained with "Reinforcement Learning for Calibrated Decisions (RLCD)"; no further technical detail published ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Third parties note training is synthetic-data only, per TypeSafe ([Requesty](https://www.requesty.ai/blog/typesafe-jev-explained)); UNVERIFIED on typesafe.ai.
- **Versions:** `jev-1.13.0` is the only listed model; `jev-latest` and `jev-preview` both resolve to it. No newer version exists as of today ([models.md](https://docs.typesafe.ai/models.md)). The parallel-questions cookbook references `jev-1.12`, so at least one earlier version existed ([cookbook](https://docs.typesafe.ai/cookbooks/parallel_questions.md)). No model changelog is published; the per-version "jaggedness" page is the nearest thing ([jev-1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)).
- **Interface:** `POST https://api.typesafe.ai/v1/systemone`; Noul / Choice (≤255 options) / Score (2 to 10 levels); probabilities + confidence on Choice and Score; `usage.input_tokens / output_tokens`; errors 401 / 422 / 429 / 529 ([api.md](https://docs.typesafe.ai/api.md)). Text only (string, JSON object, or array). No abstain. Batch = many questions per request (fan-out); no separate batch endpoint documented.
- **Limits:** 64k tokens per request (state + all questions), 32k for state + the longest single question; rate limits 100K tokens/s and 80 requests/s, "adjusting dynamically" ([models.md](https://docs.typesafe.ai/models.md)).
- **Pricing:** $0.042 per million input tokens ("$42 per Btok"); output free ([models.md](https://docs.typesafe.ai/models.md)). TypeSafe "can't prove current pricing isn't subsidized and expects prices to fall" ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)).
- **Latency claims:** 70 to 500 ms end-to-end; "40x to 200x" faster than frontier LLMs on System-One-style queries; homepage "193.6x faster, 444.6x cheaper" from workflow evals run "from a laptop on the West Coast," which TypeSafe itself says are "likely at the high end of real-world gains" ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Independent measurements: Cloudflare's lab saw median 524.1 ms / p95 536.0 ms over HTTPS ([Clef leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)); Bespoke saw median 246.7 ms via the API ([nimble](https://github.com/bespokelabsai/nimble)).
- **Benchmarks:** TypeSafe deliberately publishes no standard benchmark tables ("Lies, Damned Lies, and Benchmarks," [antibenchmaxxing](https://typesafe.ai/blog/antibenchmaxxing)); it publishes four "workflow evals" against the average of GPT-6 Astra and Fable 5.1 as reference ([launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Community numbers: Decision Index 0.2.1 = 57.91, ECE 0.074, Brier 0.3558 ([Clef leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)); JevBench v1.4.2.2 = 63.29, rank 4 of 91 ([jevbench](https://github.com/fstandhartinger/jevbench)); Nimble's 324-item holdout 93.21% ([nimble](https://github.com/bespokelabsai/nimble)); Perplexity's 11-test panel 84.51% ([pplx-decider card](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b)).
- **Notable limits (vendor-published):** nine failure modes, see A3. Cloudflare's leaderboard note: Jev's "API output drifted since the board run" (20 of the latency-sample choices changed between Sep-19 and Oct-1 runs, scores unchanged) ([leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)). This is a repeatability caveat for business-critical use.

### B2. OpenAI **Decisions API** on **gpt-6-luna**

- **Maker / dates:** OpenAI. Previewed at DevDay 2026-09-29 and opened to all developers in public beta 2026-10-06 per secondary sources ([Dealroom](https://app.dealroom.co/news/note/openai-opens-decisions-api-to-all-developers-adding-image-input-in-challenge-to-typesafe-s-jev), [The Decoder 2026-10-07](https://the-decoder.com/openai-launches-decisions-api-that-reduces-complex-evaluations-to-yes-no-or-pick-one/)); OpenRouter lists "GPT-6 Luna Decisions" with a 2026-10-06 date ([OpenRouter decisions listing](https://openrouter.ai/models?output_modalities=decisions)). OpenAI's own guide says "in public beta, and we expect to GA in the coming weeks" ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)). The DevDay recap page returned 403 to me, so the **2026-09-29 preview date is UNVERIFIED** from OpenAI directly. There is no separate "decision mode" flag; it is a dedicated endpoint.
- **What it is:** `POST /v1/decisions`, `gpt-6-luna` is "the only model currently available." It is a constrained readout of a general LLM, not a separate small model (no size disclosed) ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)).
- **Interface:** `predicate` (returns `probability`, no confidence), `choice` (`choice`, `probabilities`, `confidence`), `score` (`score` as probability-weighted mean of 0-indexed level indices, `probabilities`, `confidence`). Answers can be `type: "refusal"`. No built-in abstain: add an "other" choice. Text plus inline base64 images only (no hosted image URLs, no file IDs). Max questions per request, context limits and batch are not documented ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)). OpenRouter lists a 1.05M context ([OpenRouter](https://openrouter.ai/models?output_modalities=decisions)).
- **Pricing:** $0.10 per million input tokens; "no cache-read, cache-write, or output-token charges"; regional-processing and long-context multipliers apply ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)).
- **Latency claim:** "about 10x faster than the Responses API," no benchmark given ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)). One developer's independent replay reported ~230 ms median, 76/78 correct ([search summary; source blog UNVERIFIED]).
- **Hosted / open:** hosted only. Zero Data Retention and HIPAA for eligible customers; US and EU data residency ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)).
- **What OpenAI says it is not for:** use Structured Outputs for schema-shaped generation and function calling for tool calls ([Decisions guide](https://developers.openai.com/api/docs/guides/decisions)).

### B3. Cloudflare **Clef** and **Clef-flash**

- **Maker / date:** Cloudflare, 2026-10-01 ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)).
- **What it is:** Clef = frozen Qwen3.8-27B + rank-256 LoRA + routing head, with the Qwen vision encoder; Clef-flash = same recipe on Qwen3.5-9B. Post-training: label-smoothed cross-entropy + Brier loss for calibration + an RL objective Cloudflare also calls RLCD. Prefill-only scoring, no autoregressive tokens ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/); [HF card](https://huggingface.co/Cloudflare/clef)). Grew out of an earlier Cloudflare experiment exposing DiffusionGemma logprobs ("DiffusionGemma Jev"), which appears on the leaderboard as a separate row ([leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)).
- **Interface:** "fully Jev-compatible" `state` + `questions` (noul / choice / score), probabilities per option; images and video frame arrays accepted; 64k context (vs Jev 32k) ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)). The HF `encode_record` defaults to 16,384 tokens ([HF card](https://huggingface.co/Cloudflare/clef)). No abstain. Batch: mixed text/multimodal records in one batch on the HF code path.
- **Pricing:** not stated in the blog or model card. Hosted as `@cf/cloudflare/clef` on Workers AI ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)). **Workers AI price UNVERIFIED.**
- **Latency (self-reported, Cloudflare lab):** Clef median 209.3 ms / p95 238.6; Clef-flash 38.8 / 122.4; Jev 524.1 / 536.0 ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)).
- **Open weights:** Apache-2.0 on Hugging Face; runs with bundled custom head code; no HF Inference Provider deploys it yet ([HF card](https://huggingface.co/Cloudflare/clef)).
- **Benchmarks (self-reported):** Decision Index 61.21 (Clef) and 57.07 (Clef-flash) vs Jev 57.91; note Clef rows are `self_reported: true`, panel coverage 36 of 38 ([leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)). Clef beats Jev on BFCL, BANKING77, CLINC150+OOS, ForecastBench Brier; Jev beats Clef on MMLU-Pro (82.7 vs 65.9), GPQA Diamond (78.3 vs 48.0), When2Call, PhishNChips ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/), [HF card](https://huggingface.co/Cloudflare/clef)).
- **Stated use:** classification and routing inside agent workflows, threat intel (domain categorisation), support triage, Trust & Safety, bot classification; plus a fine-tuning/RL service, initially hands-on with forward-deployed engineers ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)).
- **Limits:** weaker than Jev on knowledge-heavy tasks; Clef-flash trails Clef on CLINC150+OOS (66.77 vs 97.43); fine-tuning can reduce general performance ([Cloudflare blog](https://blog.cloudflare.com/clef-decision-models/)).

### B4. Liquid AI **d1**, **d1-3B**, **d1-omni-600M**

The model is called **d1** (not "D1" or "LFM-D1"). Three artefacts:

- **d1 (hosted flagship).** Liquid's "first decision model"; text and images; Noul / Choice / Score with probabilities (Choice and Score also return confidence per the API docs); no architecture or size disclosed; "200 to 300 ms" per text decision; "19x to 200x less" cost than GPT-6.1 Sol and Claude Opus 5.5 (vendor claim) ([Liquid blog, 2026-10-05](https://www.liquid.ai/blog/d1-decision-model); [API docs](https://docs.liquid.ai/lfm/models/d1)). Endpoint `https://api.liquid.ai/decisions/v1/systemone`; `d1` (paid, images) and `d1:free` (text); images cost 1.5 tokens per 32×32 patch and are re-billed per question; up to 8 images per request ([API docs](https://docs.liquid.ai/lfm/models/d1)). Pricing: the blog's methodology uses $0.04 per million input tokens; the docs page gives no figure ([Liquid blog](https://www.liquid.ai/blog/d1-decision-model)). Also on Vercel AI Gateway and OpenRouter, text only for now. Earlier secondary coverage dated 2026-09-29 described a hosted text-only d1 ([MarkTechPost 2026-09-29](https://www.marktechpost.com/2026/09/29/liquid-ai-releases-d1-a-decision-model-that-returns-calibrated-probabilities-with-zero-output-tokens/)); the vision update is dated 2026-10-05 on Liquid's models page ([liquid.ai/models](https://www.liquid.ai/models)). **Initial hosted-release date UNVERIFIED** from Liquid directly.
- **d1-3B (open).** 3.1B, built from LFM2.5-VL-3B (decoder VLM); text + images; "Open-weight," day-one llama.cpp; latency 8 ms on RTX 4090, 30 ms on Apple M5 Pro, 50 ms on Jetson Orin Nano; Decision Index v0.2.1 = 48.57 (Liquid-reported, "ahead of every model under 10B"); mean of seven text tasks 82.9 vs Decider 4B 81.1 ([Liquid blog, 2026-10-07](https://www.liquid.ai/blog/d1-open); [docs](https://docs.liquid.ai/lfm/models/decision-models)). No license identifier on the page; Liquid's general LFM terms are free "until your company passes $10M in annual revenue" ([liquid.ai/models](https://www.liquid.ai/models)); **d1 license UNVERIFIED**.
- **d1-omni-600M (open, experimental).** 587M, bidirectional encoder (LFM2.5-Encoder-350M) + FastConformer audio encoder + vision encoder; text+image or text+audio; Decision Index 15.95 ([Liquid blog](https://www.liquid.ai/blog/d1-open)).
- **Limits:** results are "single runs on a small number of applications" and Liquid "wrote some of the test questions after setting up d1's pipeline" ([Liquid blog](https://www.liquid.ai/blog/d1-decision-model)); audio benchmarks are "an open problem" ([d1-open](https://www.liquid.ai/blog/d1-open)).

### B5. Perplexity **pplx-decider-v1-27b** / **v1.1** and Decisions API

- **Maker / date:** Perplexity, 2026-10-01 per multiple secondary sources ([AI Weekly](https://aiweekly.co/alerts/perplexity-open-sources-27b-decider-edges-jev-on-11-test-panel)); OpenRouter lists "Decider V1.1 27B" dated 2026-10-07 ([OpenRouter](https://openrouter.ai/models?output_modalities=decisions)). HF card gives no date. **Exact launch date UNVERIFIED from Perplexity.**
- **What it is:** 26B BF16 fine-tune of Qwen3.8-27B, multimodal (text + images), Apache-2.0 on HF; needs ~49 GiB GPU memory; no HF inference provider ([HF card](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b)).
- **Interface (hosted):** `POST https://api.perplexity.ai/v1/decisions`; models `pplx-decider-v1.1-27b` and `pplx-decider-v1-27b`; noul / choice / score with `probabilities` and `confidence` ("not the top probability and drops when the runner-up is close"); 1 to 128 questions per request; 1 to 255 options; 1 to 10 levels; < 262,144 input tokens per request; images as base64 only, ~1,000 tokens per megapixel; 10 requests/s per org ([Perplexity quickstart](https://docs.perplexity.ai/docs/decisions/quickstart)). No abstain.
- **Pricing:** $0.02 per million input tokens, output free, no per-request fee ([quickstart](https://docs.perplexity.ai/docs/decisions/quickstart)); OpenRouter shows the same for v1.1 ([OpenRouter](https://openrouter.ai/models?output_modalities=decisions)).
- **Latency:** "under 2 seconds for small inputs to about 23 seconds near the input limit" in Perplexity's own tests ([quickstart](https://docs.perplexity.ai/docs/decisions/quickstart)). No sub-second claim from Perplexity.
- **Benchmarks (vendor):** 85.71% overall vs Jev 84.51% vs base Qwen3.8-27B 74.76% on 11 benchmarks / 7,210 samples; Jev wins 5 of 11 (WinoGrande, JudgeBench, BBH, JevBench-hard, Belebele, TruthfulQA) ([HF card](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b)).

### B6. AWS **Strands Decider 2B** (Strands Labs)

- **Maker / date:** AWS Strands Labs, 2026-10-01 ([SiliconANGLE](https://siliconangle.com/2026/10/01/aws-debuts-strands-decider-2b-a-first-lightweight-decision-model-for-accelerate-agentic-workflows/), [MarkTechPost](https://www.marktechpost.com/2026/10/01/aws-strands-labs-releases-strands-decider-2b/)). This is AWS's only published decision model; Jev is **not** in the Bedrock catalog ([search of builder.aws.com posts](https://builder.aws.com/content/3Jm5jYPrskJbBEqxoNZaYYcAYk6/jev-isnt-another-llm-could-decision-models-become-a-new-layer-for-aws-agents)). ### B14. **AnyJev** (Nokia Applied Research) — training-free calibration wrapper

- **Maker / date:** Nokia Applied Research (with Tencent Hunyuan and PolyU authors); technical report arXiv:2610.00831; benchmark run dated 2026-09-22, Tacit results 2026-10-06; Apache-2.0 ([AnyJev README](https://github.com/nokia-applied-research/AnyJev)). First-release date not on the page; **UNVERIFIED** (secondary coverage 2026-09-26, [The Daily Commit](https://thedailycommit.in/story/2026-09-26/02-github-nokia-applied-research-anyjev)).
- **What it is:** `Decider` reads next-token probabilities over option labels from any open LLM; level **L0** averages out position bias over K cyclic rotations of the options and divides out the label prior (no labels needed); a "rotation budget" stops early at a certified disagreement rate. **Tacit** = self-distilled Qwen checkpoints (1.7B to 9B) that answer in one pass what the base would reach by reasoning; `adaptive=True` escalates close calls (top-two within tau) to chain-of-thought, capped at 20% of recent decisions ([README](https://github.com/nokia-applied-research/AnyJev)).
- **Backends:** transformers, vLLM (in-process and server), SGLang, llama.cpp GGUF; HTTP gateway without auth; MLX and Ollama planned ([README](https://github.com/nokia-applied-research/AnyJev)).

- **Why it matters for the talk:** it quantifies two things hosted vendors do not: how much of the error is **option-order bias**, and what fraction of decisions can be **auto-approved at a fixed risk budget**.

### B17. The two incumbents the decision models are replacing

**Fine-tuned encoders (BERT / DeBERTa / ModernBERT / SetFit / GLiClass).** The pre-Jev production standard for bounded-label classification. ModernBERT (2024-12-19): 149M and 395M encoder-only models, 8,192-token context, positioned as the slot-in BERT replacement; its authors argue decoder LLMs are "too big, slow, private, and expensive for many jobs" and cite FineWeb-Edu's filtering of 15T tokens with a fine-tuned BERT classifier at ~6,000 H100 hours versus "over one million dollars" through a cheap decoder model ([HF blog](https://huggingface.co/blog/modernbert)). SetFit: "with only 8 labeled examples per class" it is "competitive with fine-tuning RoBERTa Large on the full training set of 3k examples," needs no prompts, and is "typically an order of magnitude (or more) faster" ([SetFit docs](https://huggingface.co/docs/setfit/index)). GLiClass scores all labels in one pass with a DeBERTa-sized encoder ([GLiClass, arXiv 2508.07662](https://arxiv.org/abs/2508.07662), via [awesome-jev-alternatives](https://github.com/mturac/awesome-jev-alternatives)). What they lack: they cannot read a natural-language policy or rubric at inference time; the label set is fixed at training time. Laya, GLiNER2.5-Decide, Verdict and Lavoir are exactly this architecture retro-fitted with runtime-defined options, and they occupy the bottom of the Decision Index (1.87 to 11.21) while being the fastest rows (5.8 to 23 ms) ([leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)).

**LLM with structured output / JSON schema.** OpenAI Structured Outputs "ensures the model will always generate responses that adhere to your supplied JSON Schema," supports enums and nullable fields, surfaces safety refusals in a `refusal` field, can return incomplete output at the token limit, adds first-request latency for a new schema, and **returns no probabilities or confidence** ([OpenAI Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs)). This is the "coerce and parse" path TypeSafe positions against, and the baseline most teams run today. The shape is guaranteed; the label is still generated token by token, there is no distribution over alternatives, and you pay for output tokens.

## Part E — What they are good for / not good for (builder's synthesis)

1. **Use a decision model where the label vocabulary is closed, the rubric is explicit, and volume is high.** That is the whole design envelope: "fast, focused judgments," one factor per question, no text ([system-one](https://docs.typesafe.ai/concepts/system-one)). Routing, triage, severity, duplicate detection, guardrail checks, passage relevance, citation support are the documented cookbooks ([cookbooks](https://docs.typesafe.ai/cookbooks.md)). The economics are real: $0.02 to $0.10 per million input tokens with free output across OpenAI, Perplexity, Liquid and TypeSafe (Part D), and sub-100 ms on open models self-hosted on one GPU (Clef-flash 38.8 ms, Kev-4B 18.1 ms, d1-3B 8 ms; B3, B8, B4).

2. **Do not let the model do anything code can compute.** Counting, arithmetic, date ordering, duration windows and numeric formats are all on TypeSafe's own failure list; the model "is not a calculator" and "dates are read as text" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)). Kev's authors found date arithmetic their weakest family (0.65 vs Jev 0.95) ([kev-4b card](https://huggingface.co/jaredpalmer/kev-4b)). Pre-compute the fact in code, put the result in the state, and ask the model only the judgment.

3. **"Insufficient information" is your label, not theirs.** No API ships an abstain primitive (A2). Add an explicit `other` / `insufficient_information` option, then gate on confidence with thresholds you fit on your own labelled data; TypeSafe's example uses 0.5 to involve a human and 0.9 for destructive actions ([confidence](https://docs.typesafe.ai/confidence)). AnyJev's number is the one to remember: on raw Qwen3-8B only 7.7% of BANKING77 decisions were auto-decidable at a 5% error budget before debiasing, 46.3% after ([AnyJev](https://github.com/nokia-applied-research/AnyJev)); Kev's authors report Jev automates ~0.70 of new-source decisions at the same budget ([kev README](https://github.com/jaredpalmer/kev)). Plan for 30% to 50% of decisions to need a fallback path.

4. **Confidence is not calibrated accuracy until you measure it on your distribution.** TypeSafe says so explicitly ("depends on your domain and the performance of the model for your use case," [confidence](https://docs.typesafe.ai/confidence)); Laya "ships overconfident" ([card](https://huggingface.co/convaiinnovations/laya)); Tev1 logprobs "reflect model preference, not calibrated confidence" ([tev1](https://github.com/togethercomputer/tev1)); Nimble changed its temperature from 2.179 to 1.0 between checkpoints and warns thresholds must be retested ([nimble](https://github.com/bespokelabsai/nimble)). Measure ECE/Brier on a held-out sample of your own traffic before wiring any threshold to a money or safety action.

5. **Order your options deliberately and test the reverse order.** Jev "leans toward the first option" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)); Kev: "option order can change answers" ([kev README](https://github.com/jaredpalmer/kev)); raw open LLMs flip 23% of answers when options are reversed ([AnyJev](https://github.com/nokia-applied-research/AnyJev)). Only AlexWortega/openjev claims order invariance ([card](https://huggingface.co/AlexWortega/openjev)). A reversed-order consistency check is a cheap, strong regression test.

6. **Treat the state as hostile if any of it is user-supplied.** "The model does not treat state as hostile by default" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)); one injected line cut an open model's accuracy from 0.833 to 0.467 and it caught only 37% of deny-worthy shell commands ([AlexWortega/openjev](https://huggingface.co/AlexWortega/openjev)). For guardrail use, pair the model with deterministic checks and do not make it the sole gate.

7. **Keep the state small and literal.** Accuracy "falls as unrelated content grows" ([jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)); Laya's accuracy varies beyond ~4,000 tokens ([card](https://huggingface.co/convaiinnovations/laya)); Perplexity's latency goes from <2 s to ~23 s near its 262k limit ([quickstart](https://docs.perplexity.ai/docs/decisions/quickstart)). Large context windows (Solar 512K, Perplexity 262K, Clef 64K) are a convenience for ingestion, not a license to dump the whole document per question.

8. **Expect drift and version-pin for business-critical paths.** Jev's hosted output changed on 20 of a latency sample's choices between two community runs twelve days apart with no version change ([leaderboard data](https://clef-evals.workers-ai-mle.workers.dev/data/leaderboard.json)); TypeSafe publishes no model changelog and only one version ([models.md](https://docs.typesafe.ai/models.md)); Strands warns its own v21 vs v19 difference is "two single runs, not a measured gain" ([strands-decider](https://github.com/strands-labs/strands-decider)). If repeatability matters, open weights on your own hardware (Clef, Kev, d1-3B, pplx-decider) are the only way to freeze behaviour; the price of that is you own calibration, serving and auth (several bundled servers bind to localhost with no auth: Kev, Strands, AnyJev).

9. **Benchmarks disagree with each other; run your own.** On Perplexity's panel Jev wins 5 of 11 tasks and loses overall by 1.2 points ([pplx card](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b)); on the Decision Index Clef beats Jev but on MMLU-Pro and GPQA Jev leads by 17 to 30 points ([Cloudflare HF card](https://huggingface.co/Cloudflare/clef)); on JevBench v1.4 Jev is 4th behind three community 4B LoRAs ([jevbench](https://github.com/fstandhartinger/jevbench)); Fastino's table omits Jev entirely ([GLiNER2.5-Decide card](https://huggingface.co/fastino/GLiNER2.5-Decide)). Most "beats Jev" numbers are vendor-run on vendor-chosen panels, several trained on public benchmark test splits (AlexWortega v5; Tev1 on Banking77/SST-5 per [search coverage]). TypeSafe's own position is that benchmark tables are not evidence ([antibenchmaxxing](https://typesafe.ai/blog/antibenchmaxxing)). The only number that matters is accuracy and calibration on a frozen sample of *your* decisions, re-run on every model version.
