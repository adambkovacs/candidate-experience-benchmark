The per-call reserve follows the existing [paid runner's reservation rule](../scripts/openrouter_paid_benchmark.py): full endpoint context times the higher of listed input price and historical price ceiling, plus 4,096 completion tokens times the higher output price. It assumes no cache discount. The first four values use today's endpoint contexts. Each proposed partition exceeds one such reserve; Qwen's conditional partition exceeds its provisional reserve. Allocate the five independent partitions from the same shared master ledger, then allow at most one active request in each configuration. Up to four currently verified configurations may therefore run concurrently; Qwen is excluded until its exact endpoint passes the route check. Each worker reserves against its child partition before its call. After each response, reconcile actual charge or retain the full upper bound for an unknown charge before admitting another request in that partition. The master keeps the full $1 of allocations encumbered until reconciliation, so parallel workers cannot spend the same headroom. Stop before the next reserve would cross a child cap or the shared $10 cap. No retries or recovery calls are included. A $1 total partition is defensible with these gates, though it does not guarantee all 1,890 planned calls will complete. Concurrent configurations change the observed scheduling context; keep each condition's declared order and report client request timing rather than pure inference time.
