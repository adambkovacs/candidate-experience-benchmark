These are saved-evidence contract failures for that evaluator; they are not grounds to invent missing fields or discard the saved suffix. The checks found **zero saved request or adapter-control mismatches** across the 1,260 position records. This establishes request-byte parity and terminal position accounting, not the unchanged evaluator’s required chronology for every suffix. In particular, a terminal invalid output is not silently treated as a successful parse.

**Disposition:** all seven are **blocked for an existing-contract paired evaluation**. No paired manifest or evaluation was created. The next permissible work is an offline, versioned continuation adapter. The v2/v3 `attempts.jsonl` files contain ordered `request_started` and `request_finished` events with IDs, attempt IDs and request hashes, and the frozen manifest and reconciliation remain available. An adapter could verify each event against the exact saved raw request and terminal row, prove one non-replayed attempt per ID and the source order, and explicitly use journal order where the continuation row has no per-request timestamp. It must not fabricate `started_utc`, schema or policy hashes. Qwen 3.6 P2 needs its `development_suffix` phase accepted only with a source-bound phase reconciliation. If these checks pass, a reviewed evaluator extension may include the genuine continuation schema while preserving failed and invalid positions. If that evidence does not support a position, mark that configuration ineligible; do not fill fields by assumption. Provider calls are unnecessary for this audit.
