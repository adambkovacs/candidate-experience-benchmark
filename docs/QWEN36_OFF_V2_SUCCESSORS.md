# Qwen off v2: eight later phases after the closed suffix

Prepared 2026-09-29 for independent review. The [original v2 manifest](../results/repeatability-v1/qwen36-off-fresh3-v2/manifest.json) fixes nine ordered phases and the AkashML `akashml/fp8` Qwen route. Its first fresh1/P0 development stage stopped on DEV-006 after an HTTP 429. The [versioned never-sent suffix](../results/repeatability-v1/qwen36-off-fresh3-v2/never-sent-suffix-v1/reconciliation.json) now closes DEV-007–060 without replaying DEV-001–006. Its 60-position composite has 59 valid outputs, one retained service error, $0.0078992 known development cost, a separate $0.0299008 unknown-charge upper bound, and no pending reserve. These are observed evidence values, not a clean all-valid first pass. The private original failure response contains an account identifier; its raw file and records must stay private.

The new [successor controller](../scripts/qwen36_off_v2_successors.py) prepares only the remaining eight phases in the original order: fresh1/P1, fresh1/P2, fresh2/P2, fresh2/P0, fresh2/P1, fresh3/P1, fresh3/P2, fresh3/P0. It refuses to construct a manifest unless the exact original v2 evidence and saved suffix reconciliation recompute to the closed 59/60 composite. Its manifest binds the original manifest, suffix manifest and controller, suffix reconciliation, existing $0.15 child budget receipt, its own controller hash, route, all 60 request/input/instruction hashes for each condition, and the separate `later-phases-v1` output directory. Freezing that manifest is an offline action; no production successor manifest or stage has been created by this preparation.

Each successor smoke needs a separate path-specific review receipt before execution. It sends DEV-001–003 once and records an exclusive claim, ordered request events, cumulative raw-sidecar hashes, request timing, parsed output, usage and cost. Development needs its own receipt, a strictly finished smoke verified by the frozen [v2 verifier](../scripts/qwen36_off_fresh_repeat_execution_v2.py), and an inspection binding the smoke records, journal and raw hashes. It then sends DEV-001–060 once. Before each later phase, both smoke and development of every earlier successor phase must pass that same strict verifier. The failed first phase is admitted solely through the explicit closed suffix gate; its journal and failed DEV-006 are never rewritten.

The controller checks live model and endpoint identity, reasoning-off support, price and full $0.0299008 reserve before key access. Every request uses the existing active child partition's atomic reserve, and its frozen request hash and source bindings are checked before dispatch. A child-cap denial records the next unsent ID and stops before HTTP. An invalid output, provider error, model/provider mismatch, unknown charge or billing block stops the claimed stage with its saved evidence. There is no automatic retry, replay, provider substitution, budget increase or claim deletion. The $0.15 allocation is a ceiling, not a guarantee that 504 later smoke/development calls will fit; unexpected charges or another service failure can stop the schedule. Any later continuation would need its own never-sent-only review and versioned evidence.

The [offline tests](../tests/test_qwen36_off_v2_successors.py) use persisted synthetic manifests and the real original `finished()` verifier to exercise closed-suffix admission, full request/source drift, budget binding, duplicate claim, successful smoke-to-development-to-next-phase gating, tampered predecessor evidence, route rejection, and a cap stop with zero HTTP calls. They do not perform inference or allocate funds. This handoff is for independent code and evidence review before an operator freezes a production successor manifest or authorizes each stage receipt. Any eventual report must retain DEV-006 in the fixed 60-position denominator and label the series a descriptive continuation with changed timing, not a clean matched three-pass estimate.
