# SemIf generated repeat: two passes per prompt closed

The [fresh generated plan](../results/repeatability-v1/semif-generated-fresh-v1/manifest.json) schedules three P0/P1/P2 passes, nine 60-review development phases in total. The first [P0](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P0/development.completion.json), [P1](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P1/development.completion.json) and [P2](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P2/development.completion.json) phases and second [P0](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P0/development.completion.json), [P1](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P1/development.completion.json) and [P2](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P2/development.completion.json) phases are closed in this [source-bound report](../public-site/semif-generated-repeats.json). Each saved 60 responses. Both passes matched all four provisional references on **35/60 for P0, 26/60 for P1 and 43/60 for P2**. The third pass for each prompt remains outside this publication snapshot, so no three-pass range is available.

P0 had eight invalid responses, P1 had 22 and P2 had two. Every invalid response ended with `stop` and returned the same JSON schema text instead of four classification values. The [P0](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P0/development.raw.jsonl), [P1](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P1/development.raw.jsonl) and [P2](../results/repeatability-v1/semif-generated-fresh-v1/fresh1/P2/development.raw.jsonl) raw captures and parsed records in the feed retain those outcomes. P0's invalid IDs were DEV-002, DEV-020, DEV-029, DEV-040, DEV-044, DEV-051, DEV-055 and DEV-060; P2's were DEV-029 and DEV-055. The feed lists all 22 P1 IDs. Invalid positions remain in every fixed 60-review score denominator. Validity describes response format; agreement describes a match to the reference.

The second [P0](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P0/development.raw.jsonl), [P1](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P1/development.raw.jsonl) and [P2](../results/repeatability-v1/semif-generated-fresh-v1/fresh2/P2/development.raw.jsonl) raw captures each match their first-pass counterpart on all 60 reviews. Validity positions also repeat: P0 has 52 valid and eight invalid in each pass, P1 has 38 and 22, and P2 has 58 and two. No four-field answer changed among reviews valid in both passes: **0/52 observed flips for P0, 0/38 for P1 and 0/58 for P2**. The same invalid positions are excluded from each shared-valid comparison but remain in each fixed 60-review score. These are two-pass observations on the same reviews, not three-pass stability results or guarantees about later runs.

P1 scored nine fewer fixed-denominator all-field matches than P0. Fifteen P0-valid reviews became invalid in P1; only DEV-002 moved from invalid to valid. Among the **37 reviews valid in both**, two changed a four-field answer, DEV-013 and DEV-024, but shared-valid all-field agreement stayed **25/37 in both**. The fixed-60 score drop therefore reflects changed output validity as well as the common-set classifications; it is not a nine-review decline on a constant valid set.

P2 scored eight more fixed-denominator all-field matches than P0. Six P0-invalid reviews became valid in P2, and none moved from valid to invalid. Among the **52 reviews valid in both**, six changed at least one classification: DEV-001, DEV-006, DEV-013, DEV-018, DEV-049 and DEV-054. All-field agreement on that shared-valid set rose from **35/52 to 39/52**. Four of the six newly valid reviews also matched all four reference fields in P2. Against P1, P2 scored 17 more fixed-denominator matches; among the 38 reviews valid in both, six changed answers and shared-valid agreement rose from **26/38 to 29/38**. Another 20 P1-invalid reviews became valid in P2. These score differences combine validity turnover and changed classifications. They do not isolate an effect of the added instructions.

Summed client-observed request time differed despite the identical raw outputs: **616.33 versus 427.30 seconds for P0**, **742.83 versus 876.27 for P1**, and **506.19 versus 389.87 for P2**, first then second pass. Each P0 pass returned **96,930 input and 4,680 output tokens**; each P1 pass returned **107,550 and 8,070**; each P2 pass returned **162,930 and 3,204**. These times are not isolated model inference time, and local hardware and electricity cost were not measured. The frozen plan specifies local MLX, temperature zero, thinking disabled, one attempt per review, and a fresh process and model load for each stage. It binds the intended requests without sending reference labels to the model.

The [earlier SemIf generated P0/P1/P2 observations](SEMIF_GENERATED_FRESH_REPEAT_ADMISSION_2026-09-28.md) are excluded from this fresh series. Their P2 run has 59 saved responses and an unknown started outcome at DEV-033; it cannot supply a fresh pass or be silently replayed. The [native SemIf study](SEMIF_REPEAT_FINDINGS_2026-09-28.md) uses the same verified weights but scores options through a different interface. Its three native modes each produced 60 valid classifications per pass, with 35/60 or 36/60 all-field matches. Matching one of those scores here does not make the methods interchangeable.

All references are version 0.2, AI reviewed and provisional. The same 60 synthetic reviews recur across planned passes, so later responses will not be independent cases. The [offline reporter](../scripts/build_semif_generated_repeat_findings.py) verifies stage receipts, saved stream events, raw responses, parser outcomes, completion hashes and source bindings before reporting a closed phase.
