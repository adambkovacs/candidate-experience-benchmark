## Separate continuation required

The existing [DeepSeek interrupted-prefix continuation](../scripts/deepseek_low_interruption_continuation.py) and [Qwen second-interruption continuation](../scripts/qwen36_off_v2_second_interruption.py) are useful reviewed patterns, but neither can run Gemma directly. Each binds the old claim, journal, raw attempts, frozen source and budget; accounts a failed attempt's unknown cost at its full reserved upper bound; seals and reconciles the old child; then admits only the never-sent frozen suffix under a new versioned manifest and budget partition. Both mark `clean_matched_three_eligible=false`. Gemma needs its own source-bound versioned implementation and review receipts; the frozen v2 controller, plan, attempts and ledger history must stay intact.

The recovery sequence for separate approval and implementation is:

1. Independently re-verify the SHA-256 bindings and ordered `DEV-001`–`DEV-007` stopped prefix above. Preserve the 429 and all six earlier outcomes; do not retry or reinterpret `DEV-007`.
2. Under the reviewed [v3 budget ledger](../scripts/openrouter_budget_v3.py) and [partition reconciliation](../scripts/paid_budget_partitions_v3.py), explicitly account `DEV-007` as `unknown_cost_accounted_as_upper_bound` at **$0.01974272**, with the original attempt evidence hash and reason, then seal and reconcile the old child. This audit has not done so. Do not make another request while its reserve is pending.
3. Create a Gemma-specific versioned continuation plan and controller that bind the original stopped artifacts, source and request hashes, current budget state, and a new root-reviewed receipt. Its only initial request list is frozen fresh1/P2 positions 8–60, `DEV-008`–`DEV-060`, in order. A separate allocated child cap and verified live endpoint are required before dispatch. The 53 records' *per-attempt reserved maximum* would total $1.04636416 if all were simultaneously reserved; that is a planning bound, not observed spend or an approved allocation. The actual budget admission must calculate available master headroom and the new partition cap under lock.
4. Give the suffix its own claim, journal, raw responses, attempts and completion verification. A later successor may separately admit the remaining planned conditions only after binding both the original interrupted prefix and verified suffix. The original `fresh1/P2` phase remains stopped; no later stage should be called a clean three-pass matched run on the strength of this continuation. Reports should retain `DEV-007` as a failed/unknown-cost record and distinguish the 53 later requests from the original dispatch. A genuinely clean matched-three series would require distinct new full passes and authorization.

The offline candidate [Gemma continuation controller](../scripts/gemma26_v2_continuation.py) now implements these gates as a distinct `interruption-continuation-v1` tree. It verifies the exact stopped prefix and ledger prefix, requires explicit upper-bound accounting and master reconciliation before `freeze`, then requires a separately allocated v3 child budget manifest. It selects `DEV-008`–`DEV-060` for the first suffix and retains the original frozen request bytes for six later condition pairs (`fresh2` and `fresh3`, each smoke then development). Its manifest sets `clean_matched_three_eligible=false`. Every future stage needs a hash-bound root receipt; development also needs a reviewed smoke inspection. `audit-prefix` and the [focused offline tests](../tests/test_gemma26_v2_continuation.py) are read-only. **No continuation manifest has been frozen, no new child has been allocated, and no continuation inference has run.** The planned later stages remain conditional on prior strict closure, available budget, current route checks, and separate root admission; if a stage stops, its successors remain blocked.

## Public archive hold for this error

The 429 provider body contains a top-level **account `user_id`**. The same body is embedded as a JSON string in the original attempts and responses, and base64-encoded in the wire capture. A simple literal grep over the files can miss it. The wire headers recorded for this error are `cf-ray` and `content-type`; the body is complete. Do not stage these raw files into a public repository. The original files must remain unchanged in private evidence. Before publication, use a [public evidence export](PUBLIC_EVIDENCE_PRIVACY.md) that parses nested JSON strings and decoded wire bodies, removes the account identifier and any other private account metadata, binds original and public SHA-256 values, and checks that IDs, statuses, request hashes, predictions, timing, usage, observed costs and the unknown-cost reservation remain identical. Re-verify the public files themselves before staging; no existing ignore rule protects these raw paths from manual staging.

The new controller has a separate `export-public-prefix` command targeting only `interruption-continuation-v1/public-prefix-v1`. It would create new redacted copies of the original attempts, responses, and wire capture plus a private/public hash map; it does not change the originals or prior exporter inventories. Its projection removes structured account fields inside objects, embedded JSON strings, and decoded wire bodies, while preserving the saved outcome fields. It also marks **manual privacy review required** before any public archive. This export command has not been run on the real evidence in this audit.
