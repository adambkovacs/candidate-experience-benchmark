# Website language review, 1 October 2026

**Initial verdict: REQUEST-CHANGES.** This source-level review found two reachable wording failures in the main result path. The other three findings were smaller clarity improvements. I inspected the dynamic text in [app.js](../public-site/app.js), [findings.js](../public-site/findings.js), and [repeats.js](../public-site/repeats.js), with the saved public data. The reader is a hiring or business leader first, with technical evidence available on demand. The resolution and test boundary appear below.

1. **BLOCKING: Incomplete runs appear to have final scores.** The [condition cards](../public-site/app.js#L92-L99), [run list](../public-site/app.js#L145-L159), and [detail panel](../public-site/app.js#L233-L239) printed a numeric metric followed by `/ 60` whenever the feed had one, even when `complete(run)` was false. The [public feed](../public-site/data-provider-errors-v1.json) contains two such runs: SemIf generated P2 has 59 saved records and 42 recorded all-four matches; Qwen 4B thinking P2 has 59 and 48. A `PARTIAL` badge alone did not stop a reader treating `42 / 60` or `48 / 60` as final. The [repeat view](../public-site/repeats.js#L484-L489) says incomplete passes are not zero scores. **Resolution:** retain each recorded count and the fixed denominator, but label it **"Partial tally"**, show saved and missing counts, and say **"not a final score"** beside the value and in the detail panel.

2. **BLOCKING: The prompt headline claimed a cause the comparison cannot establish.** [findings.js](../public-site/findings.js#L30-L35) said decision-tree instructions **"produced lower scores"** and its deck said **"Adding the decision tree ... worsened"** comparisons. The saved [prompt comparison](../public-site/findings-provider-errors-v1.json) supports 21 lower, 14 unchanged, and 4 higher P2 scores than P1 among 39 audited first-pass setups. It does not isolate the instruction change from run variation; the [run explorer](../public-site/app.js#L101-L102) warns that a score difference does not establish a prompt effect. The replacement headline names both versions before the codes: **"The decision-tree version had fewer matches than the classifier-instruction version in 21 of 39 audited setups."** The deck gives the 4/14/21 counts and combined 21 fewer matches as first-pass observations, then points to repeats. This reports what was observed without attributing it to the decision tree.

3. **RESIDUAL: "Jev reference" can sound like the correct answer.** The extra comparison row in [app.js](../public-site/app.js#L70-L79) calls Jev a "reference," while the [method text](../public-site/index.html#L131) uses "reference answers" for provisional labels. A nontechnical reader could conflate a model run with the scoring key. Change **"Jev reference outside the first eight shown"** to **"Jev comparison row outside the first eight"** and **"Jev P0 reference · different prompt version"** to **"Jev P0 for context · different prompt version."** Keep the separate provisional-reference warning intact.

4. **RESIDUAL: The comparison cohorts lead with research terms before their meaning.** [findings.js](../public-site/findings.js#L15-L29) names cohorts "Audited hosted and subscription pairs," "Gemini hosted observations," and "Local historical-baseline pairs." These labels ask a hiring leader to decode the method before seeing the result. Use **"Prompt comparisons checked against saved records," "Earlier Gemini prompt comparisons,"** and **"Earlier local prompt comparisons."** Keep the exact cohort identifiers and evidence links in each expandable table for implementers. The current "More / same / fewer matches" legend should remain because it explains the chart without overstating cause.

5. **RESIDUAL: The repeat section started with a configuration code and postponed its plain-language status.** [repeats.js](../public-site/repeats.js#L427-L433) labeled the main selector "Configuration"; [its summary and study details](../public-site/repeats.js#L484-L509) then led with a technical series name and phrases such as "prompt/pass combinations," "native L1 calibration," and "content-free prior." The detail disclosure is appropriate for implementers, but the first sentence should orient everyone. The selector now says **"Model and test setup."** The visible summary starts with **"X of Y planned tests have final results for the same 60 fictional comments."** It retains the failure and validity caveat. The specific unsent count stays in the data-driven DeepSeek detail, so a later continuation cannot leave a stale hardcoded number in the shared summary.
