# Analysis coverage review, 7 October 2026

## Finding and scope

The saved work supports a useful comparison of dedicated decision models, prompted general LLMs and possible combinations, but the public report does not yet make that comparison in one place. It already presents the individual runs, prompt pairs, repeat changes, field confusions and outcome failures. The published combined feed now includes Perplexity's nine closed stages, and the seven-native P0 review panel joins exact answers for all 60 reviews. A joined dedicated-versus-general case comparison and a tested combination rule are still missing. All figures below concern the same 60 synthetic development reviews and provisional v0.2 reference labels. They do not estimate performance on new reviews. The same restraint applies to time and effort. The reports have client-observed request duration, sometimes CLI-reported API duration, but lack a common pure inference-time measure. OpenRouter native calls classify one review at a time; Sonnet batches ten. A cross-route speed league table would mix request patterns and transport. Within the matched Sonnet 5.5 series, xhigh P0 remains **58/60** in all three passes and uses about **2.47 times** low effort's output tokens across its nine cells, without a consistent score gain. This is an effort-setting observation within one CLI series, not a model-size law. [Timing definitions](ANALYSIS_REFRESH_2026-10-02.md) · [Sonnet usage](../public-site/sonnet55-fresh-matched3.json).

## Findings added after Perplexity and the seven-model review panel

Perplexity returned usable classifications for all 540 development positions. Every one of its nine stages matched all four reference fields on 54/60 reviews. Same-prompt repeat predictions were identical; P0 and P2 also agreed with each other. P1 changed two fields on DEV-029: follow-up gained a reference match and sentiment lost one. The unchanged total therefore hides a changed decision. [Saved findings](../results/perplexity-decider-v1/full-v2/findings.json) · [Saved predictions](../results/perplexity-decider-v1/full-v2/public-projection.json).

In the published seven-native-model first-pass P0 panel, all seven matched the complete reference vector on 26/60 reviews. At least one disagreed on the remaining 34. DEV-029 and DEV-030 were missed by all seven. Selecting the correct model after seeing the reference would reach 58/60, but that hindsight ceiling supplies no rule for choosing a model on a new review. Keep reference ambiguity visible beside these examples. [Review-level evidence and source hashes](../public-site/disputed-reviews-v1.json).

The earlier three-model cost frontier above is historical and explicitly limited to that subset. Adding Perplexity changes it: its first P0 pass matched 54/60 at $0.01542736 observed development cost, compared with Clef's 54/60 at $0.03184656. Clef is no longer on that expanded P0 cost/agreement frontier. Equal aggregate scores do not mean the models made the same field-level decisions. This is an observed charge comparison on the same reviews through OpenRouter, under different model routes, not a controlled claim about training architecture. [Perplexity charge evidence](../results/perplexity-decider-v1/full-v2/public-projection.json) · [Clef charge evidence](../results/clef-openrouter-v1/findings-v1/findings.json).

## Next analysis work, in priority order

1. **Extend the existing case grid.** The published seven-native-model P0 panel already covers all 60 reviews. Add source-bound general-LLM runs, comparing shared IDs while exposing differences in controls. Use one row per `DEV` ID; columns for exact model, route, interface, prompt and pass, with each four-field answer, output status and source. Filter by reference class and condition. Start with fully saved P0 first passes. Give each case one weight regardless of how many repeats it has. Show disagreements between dedicated and general models and the reference, including a separate view of adjudication-sensitive cases. [Existing historical case export](../results/comparison/cases.json) · [Current run sources](../public-site/analysis-refresh.json).
2. **Measure a defined combined workflow offline.** Predeclare a feasible rule, such as one primary classifier plus a second review or abstention when outputs disagree or native confidence is low. Then calculate accepted coverage, field confusion, all-four agreement, abstentions and incremental observed cost on shared IDs. Compare it with each component and with a simple baseline. Label the 56/60 OpenRouter oracle bound as an upper bound only. Do not select or tune a rule on these 60 and claim out-of-sample gains. [Native per-case evidence](../results/clef-openrouter-v1/findings-v1/findings.json) · [Reference caveats](REFERENCE_REVIEW_V1.md).
3. **Make error concentration visible.** For each selected matched cohort, show errors by case and field, a reference-by-prediction heat map, positive-class recall and false positives, and whether high-confidence errors cluster on the same IDs. Separate all-four errors from individual-field errors and mark invalid, failed and never-sent outputs. Add the DEV-006 proposed revision and DEV-013/030 human-adjudication sensitivity as a separate, versioned calculation. [Reference review](REFERENCE_REVIEW_V1.md) · [Outcome accounting](CLEF_OPENROUTER_FINDINGS.md).
4. **Add a controls ledger beside each cross-model chart.** State the exact checkpoint and adaptation, provider/interface, prompt text, policy placement, review batching, effort, pass, cost basis and time basis. Compare within matched controls first. Treat dedicated training lineage, model size, route and prompt effects as jointly confounded when several change at once. Do not pool three repeats as 180 independent reviews or convert a first-pass difference into a causal claim. [Category rule](REPORT_CATEGORY_REVIEW_2026-10-02.md) · [Sonnet protocol](SONNET55_MATCHED3_V2_CONTINUATION_2026-10-02.md) · [Native route plan](../results/clef-openrouter-v1/plan.json).

The present data can support a richer descriptive report without new inference. Claims about general accuracy, a deployed ensemble benefit, probability calibration, model-size effects or pure inference speed need either a predeclared validation set, adjudicated labels, comparable controls or new instrumentation. The remaining full-roster gaps must stay visible beside the closed subsets. [Current goals](CURRENT_GOALS.md) · [Completion audit](COMPLETION_GAP_AUDIT_2026-10-07.md).
