# DeepSeek V4.1 Flash high: offline execution candidate

The [three frozen fresh plans](../results/repeatability-v1/deepseek-high-fresh-matched3-v1/) use exact saved P0, P1 and P2 request bodies in three rotated passes. Each request is a single input-only record. Historical attempts remain descriptive because their continuation schedule was interrupted; their invalid and failed outcomes remain in the source evidence and are not replayed. The [planner](../scripts/deepseek_high_fresh_repeat_study.py) reconstructs the prompts, input order, schema, request hashes and historical control limits. It also binds the immutable [lower-price route observation](../results/repeatability-v1/deepseek-low-fresh3-v2/lower-price-endpoint-audit-v1.json).

The [execution wrapper](../scripts/deepseek_high_fresh_repeat_execution.py) loads the reviewed [Qwen27 executor](../scripts/qwen27_fresh_repeat_execution.py) in a private module. It retains that controller's bounded HTTP capture, exclusive child-ledger reserve and settlement, durable phase claim and request journal, strict ordering, and no-replay behavior. The separate [execution manifest](../results/repeatability-v1/deepseek-high-fresh-matched3-v1/execution-manifest.json) binds the exact wrapper, shared executor, planner, transport, budget and admission sources, tests, and all three committed plans. Its status is `offline_frozen_not_approved`. The proposed $0.90 child partition is **unfunded**. Preparation made no key read, provider completion, budget allocation or phase claim.

The saved historical request price ceiling remains $0.10 per million prompt tokens and $0.50 per million completion tokens. The separately saved current endpoint lists $0.03 and $0.50 per million. Before any future stage the wrapper requires a fresh, exact `open-inference/fp4` endpoint with the reviewed price, status, limits, parameters and high reasoning control. It recomposes all 60 request bodies under that route without changing their bytes. The maximum per-call reservation remains $0.1069056 because the original request price ceiling is higher than the current prompt rate. A future funded ledger must reserve that amount before each request; an unknown charge retains it and stops. The $0.90 cap does not guarantee that all 567 scheduled calls will fit.

Each condition first runs a distinct three-record smoke, which must be valid, known-billed and explicitly inspected before the 60-record development phase. The frozen development policy continues only after a fully observed, known-billed intrinsic invalid response; it stops on a service failure, unknown charge, route mismatch or budget failure. The additional completion verifier binds the full 60 IDs, request and raw response bytes, current route, known charges, journal order and each retained invalid's continuation eligibility. It does not score an open or stopped phase as complete. Returned usage and client request-to-record duration are observations; unavailable cost and pure inference time are not represented as zero.

The shared transport durably captures at most 16 MiB of a 200 or HTTP-error body, response status and selected headers before parsing. A malformed or truncated 200 with unknown billing retains its full reserved bound and cannot be retried in place. Raw provider responses remain local until separately sanitized for publication.

Offline tests use mocked HTTP transport with a real temporary budget ledger. A separate test allocates a real **temporary** master-to-child partition, admits its exact $0.90 cap through the production `budget_gate`, and rejects mismatched provider and effort. The tests also exercise the inspected three-call smoke to 60-call development transition, a known-billed length invalid that remains in the completed phase, malformed 200 and bounded 503 evidence, unknown reserve and no replay, live route drift, receipt mismatches, source binding and private-module isolation. No live execution is approved by these tests. Root must independently review this exact manifest, fund a child partition inside the existing aggregate cap, provide phase-specific receipts and inspect every smoke before dispatch.
