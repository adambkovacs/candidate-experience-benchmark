# Mistral repeat 2 P1, never-sent suffix

This controller is limited to DEV-044 through DEV-060 for `openrouter-paid-mistral-small32-24b-venice-not-applicable`, repeat 2, P1. DEV-001 through DEV-042 already returned valid outputs. DEV-043 returned a Venice HTTP 429 and remains a service error with unknown actual charge. Its $0.02502400000 reservation was explicitly retained at the full upper bound in [the accounting receipt](../results/repeatability-v1/openrouter-paid-mistral-small32-24b-venice-not-applicable/dev043-unknown-cost-bound-v1.json). The suffix never dispatches DEV-043.

The [controller](../scripts/mistral_p1_never_sent_suffix.py) reconstructs the exact 60 frozen requests from the [repeat 2 manifest](../results/repeatability-v1/openrouter-paid-mistral-small32-24b-venice-not-applicable/repeat2/manifest.json). It checks the original claim, journal, attempts, raw response sidecars, inspected smoke, root review, partition manifest, and DEV-043 accounting receipt by byte hash. It also checks the child ledger's accounting event against that receipt before admitting any new phase. The original files stay untouched. A new claim and journal use exclusive creation, so a prior suffix attempt cannot be restarted by this command.

`prepare` writes a draft manifest under `repeat2/P1/never-sent-suffix-v1`; `freeze --draft PATH` validates it and writes a frozen copy. Both are offline. Record the printed SHA-256. An independent root review must then approve that exact hash with schema `mistral-p1-suffix-root-review-v1`, the original review and budget-manifest hashes, the controller hash, partition ID `mistral32-repeat-v1`, approved phases, a substantive cooldown note, and `cooldown_not_before_utc`. The review must choose `capacity_probe_policy: required` or `waived_with_reason`; a waiver needs `probe_waiver_reason`. The controller cannot establish that Venice has recovered from a rate limit merely because time has passed.

A three-call `capacity-probe` is optional and uses the frozen DEV-001 through DEV-003 payloads as **separate capacity observations**, never as new development outcomes. It needs its own approved phase, budget reservations, raw evidence, and journal. The root can inspect a successful three-call probe with `inspect-probe`; development under a required-probe policy needs a new review receipt that binds the inspection file by path and SHA-256. An attempted probe cannot be waived after the fact. Probe failure or unknown charge stops admission. The historical inspected P1 smoke remains historical evidence; it is not a fresh capacity observation.

Only `development` dispatches the 17 never-sent positions, in canonical order and with zero retries. Each request gets a durable intent and child-budget reservation before HTTP. Bounded response bytes are durably saved before parsing; HTTP error bodies are saved as separate raw sidecars. If an HTTP error body ends early, the captured partial bytes and `IncompleteRead` marker are saved before settlement, and the charge remains unknown. Any service error, unknown charge, identity/control failure, or noncontinuable output stops the suffix. A process crash after reservation or start leaves an ambiguous position and no automatic resend. Future resolution would require a separately reviewed action. The same Venice FP8 endpoint, quantization, price ceilings, full-context reservation, frozen payload, and $0.15 child cap are checked again before dispatch. This document and its tests do not authorize a live call or load credentials.

`reconcile --manifest PATH --sha256 HASH` is offline and prints all 60 positions. It verifies suffix request identity, journal order, response attribution, and known-charge settlements against the child ledger. It reports never-sent, reserved-but-not-started, started-without-finished, valid, and failed positions separately. If all 17 suffix positions finish valid, the composite is **59 valid plus one historical service error out of 60**. `strict_complete_pass` remains false. The original journal still says `phase_stopped`; the existing wave order gate still blocks repeat 2 P0 and repeat 3. A later, separately reviewed gate and report must record the changed timing before those phases can proceed. Neither coverage closure nor a provider cooldown repairs the original counterbalanced schedule.

