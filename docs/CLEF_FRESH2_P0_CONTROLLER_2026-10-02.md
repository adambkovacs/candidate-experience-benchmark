The controller requires a fresh billing-page byte hash and a locked, reviewed head of the shared [$10 postapproval ledger](../results/postapproval-paid-work-2026-10-02.jsonl) for **each** phase. It pins the immutable [post-first-pass authority snapshot](../results/clef-native-v1/postapproval-ledger-after-full-p0.jsonl) as a prefix. Other work can consume capacity between grants; a changed ledger head stops before a stage claim or request.

The [controller](../scripts/clef_native_fresh2_p0.py) has one offline `verify` command and a separately gated `run --execute` command. The latter accepts one model and one phase, either `smoke` or `development`; it cannot admit another pass or prompt condition. Each stage needs its own exact reviewed grant with `approved: true`, `authorized_by_user: true`, a reviewer, model/phase/stage identity, manifest/controller/bridge hashes, account-ID hash, the current billing-source hash, the exact phase hold, a locked shared-ledger head hash, the existing $10 authority approval hash, `pause` exhaustion policy and a bounded wait. No grant is included in this checkpoint. The checked grant is a stage-specific admission, not a grant for the remaining matrix.

The full development grant also binds an independently signed `clef-native-fresh2-p0-smoke-review-v1` receipt. That receipt must name the model and stage, the admission manifest, and the saved smoke completion, raw and record hashes. The controller checks three valid ordered DEV-001–003 records, the smoke's durable evidence hashes and the same account ID before accepting it. A stopped smoke, missing inspection, changed controls or different account blocks the full run. The inspector must read all three raw responses and their native distributions; a passing parser alone does not approve the route.

Once a stage is admitted, the controller writes a unique cross-provider hold before creating its exclusive claim. Its local append-only ledger reserves the full-context bound **before each request**. The journal records `reserved`, `started` and `finished` with an immutable attempt ID. An HTTP or provider-envelope failure stops the phase; a missing connected-app result remains an unknown outcome and stops the phase. Neither is retried. The terminal receipt binds claim, journal, raw and parsed records and lists every never-sent ID. Format-invalid responses remain saved outcomes. A claim or hold prevents rerunning the same stage; any continuation would need a separately reviewed version.

The connected-app handoff writes an account-redacted request file under the stage's `app-bridge/` directory. The operator must save the actual `mcp__codex_apps__cloudflare_execute` result, its outer tool result and a dispatch record with the attempt's request hash, then call the controller's `submit` command with that request file and saved app result. The runner checks the response against the request, saved inner result, outer tool result and dispatch record before parsing. The bridge never substitutes a direct HTTP call. Client wait time is saved as client time, not pure inference latency. The runner reads only `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN` or their `CF_` aliases from process variables and, when supplied, `--env-file`; it never prints their values.

Before any live stage, independently review the actual account, current model route and price bytes, the exact grant, the authority ledger head and available cap, and the 60 input-only requests. For a full stage, review the new smoke evidence and receipt as a separate step. `python3 scripts/clef_native_fresh2_p0.py verify` is safe offline. No grant, hold, connected-app request or model inference was created by this preparation.
