# DeepSeek low lower-price successor admission

The [saved endpoint checks](../results/repeatability-v1/deepseek-low-fresh3-v2/live-endpoint-check-2026-09-29.md) show why the frozen [v2 runner](../scripts/deepseek_low_fresh_repeat_execution_v2.py) stopped before fresh1/P1 development: after the endpoint became available, its prompt price was `0.00000003` USD/token instead of the frozen `0.0000001`. A separate [immutable public catalog snapshot](../results/repeatability-v1/deepseek-low-fresh3-v2/lower-price-endpoint-audit-v1.json) binds the selected endpoint and raw GET response hashes. The selected provider, quantization, context, completion and cache-read prices, supported parameters, and request controls did not change in that check. Both checks are dated observations, not promises that the route remains available.

The frozen [manifest](../results/repeatability-v1/deepseek-low-fresh3-v2/manifest.json) has SHA-256 `c1c685db6a4e6a9c4b8376d1d11adc98942fcf9f66eb137daed867b1dc2c5004`. Fresh1/P0 smoke and development and fresh1/P1 smoke are closed. Fresh1/P1 development has no claim, journal, raw response, or record file. The child partition is funded at $0.25. This amendment starts with that never-sent development stage; it neither replaces earlier responses nor changes the original manifest, runner, or review receipt.

The versioned [successor wrapper](../scripts/deepseek_low_price_successor_v1.py) calls the old runner's admission checks, including its predecessor and no-replay guards. A separate root-reviewed receipt for the exact stage must bind the old manifest, budget, old stage review, immutable route snapshot, original runner, successor wrapper, and successor tests by SHA-256. `amendment_fields()` exposes the exact expected receipt fields to an offline verifier; `verify_amendment()` requires exact equality. The old stage review remains intact and still identifies the old runner. The additional receipt identifies the code and price exception actually used.

Before key access or claim, the wrapper fetches public catalog metadata and requires one available `open-inference/fp4` endpoint. It compares the selected endpoint's model ID, provider, tag, quantization, context length, prompt and completion token limits, and supported parameters with the frozen endpoint. It requires the full pricing object to match after changing only `pricing.prompt` to `0.00000003`; uptime and new descriptive fields may vary. It then checks low-reasoning support and reconstructs every stage request against the frozen request, input, and instruction hashes. The provider `max_price` request fields stay at $0.10/M input and $0.50/M output. The old per-call reserve stays $0.1069056 because `reservation()` uses those ceilings as floors; the lower advertised prompt rate cannot reduce the reserved upper bound. The wrapper scopes the verified endpoint substitution to one dedicated process invocation of the old `execute()` function. That function fetches the catalogs again and rejects further drift before loading a key or claiming the stage. Its request loop, raw capture, billing settlement, unknown-charge hold, and no-retry behavior remain unchanged.

For the first amended stage, the supplementary receipt path is `results/repeatability-v1/deepseek-low-fresh3-v2/phase-02-development.price-amendment.root-review.json`. The existing `phase-02-development.root-review.json` is still required. Future never-sent stages each need their own old stage review, smoke inspection where applicable, fresh price check, and separate supplemental review. The wrapper rejects phase 01 and the already-closed phase 02 smoke.

The public [additional-hosted reporter](../scripts/build_additional_hosted_fresh_repeat_findings.py) currently verifies the old runner and old review only. Before publishing an amended stage, its owner must bind the supplemental receipt and wrapper/test hashes, verify `amendment_fields()` against that stage, and distinguish the live endpoint's lower price from the frozen route snapshot. This report change must not substitute a public price for the old manifest hash or erase the historical endpoint metadata. No amended stage has run yet.

The tests exercise the exact lower price, unchanged reserve and request digests, higher-price and identity rejection, wrong request rejection, old-stage exclusion, exact supplemental receipt, and scoped substitution. One test runs the original request loop and a temporary real child ledger with fake catalog, key, and completion transport. No test allocates the production budget or sends a model request. The wrapper and receipt require independent review before a live dispatch.
