# Claude subscription repeat roster

The separate [roster controller](../scripts/claude_repeat_roster.py) covers 15 eligible batch-10 Claude configurations. It excludes the completed [Opus 5.5 medium lane](../scripts/claude_repeat_study.py). The four Fable 5.1 configurations now have frozen manifests and two closed repeat passes for P0, P1, and P2: [saved Fable evidence](../results/repeatability-v1/claude-roster-v1/) and the [offline report builder](../scripts/build_claude_roster_findings.py) cover 24 completed 60-record development phases and 24 inspected three-record smokes. The remaining eligible roster configurations are separate work. Eligibility was derived from the saved [coverage ledger](../results/repeatability-v1/coverage.json), each [paired manifest](../results/prompt-comparison-v1-2026-09-24/paired-reports/), matching normalized six-batch attempts, and frozen subscription preparation files. Historical non-`ok` batches are not promoted into eligibility.

The table is shorthand; the controller's `ROSTER` is the exact allowlist. Max and ultra are excluded. Every listed historical condition has six saved `ok` batches of ten records. The controller checks the exact historical system instruction, input payload, JSON schema, request digest, model, effort, auth method, and saved request evidence. It uses only the 60 [development inputs](../data/pilot/inputs.jsonl); reference labels do not enter requests.

Each configuration keeps its observed historical order. If the first pass was `P0,P2,P1`, repeat two is `P2,P1,P0` and repeat three is `P1,P0,P2`. If it was `P0,P1,P2`, the rotations are `P1,P2,P0` and `P2,P0,P1`. A condition cannot start before earlier conditions in its repeat close, and repeat three cannot start before all repeat-two development phases close. The smoke for each condition uses DEV-001 through DEV-003. A reviewed inspection of its saved attempts, records, and journal is required before the six development batches.

The repeat runtime is pinned to Claude Code `2.1.282 (Claude Code)` at `/Users/adamkovacs/.local/share/claude/versions/2.1.282`. The historical CLI was `2.1.280 (Claude Code)`. That patch difference, hidden rendering, and serving revision remain limitations. The controller uses a fresh isolated CLI directory per batch, Claude.ai subscription auth, the frozen command builder and batch parser, zero controller retries, and a durable sanitized raw capture before parsing. A non-`ok` or ambiguous batch stops the phase. Existing claim or journal files block replay.

Before a future smoke or development admission, root must save a fresh private subscription preflight **outside this public repository**. The private file contains the operator, CLI version, Claude.ai and first-party auth identity, credits-off and extra-usage-disabled controls, current session and weekly usage, and a UTC check time. The controller applies the completed lane's 30-minute freshness and below-95-percent guards. It checks live `auth status` and CLI version again before a claim or model call. It will not admit a different executable path.

A phase-specific public root review must contain only `schema`, `approved`, `configuration_id`, `repeat`, `manifest_sha256`, `controller_sha256`, `mechanics_sha256`, `private_preflight_sha256`, `cli_path`, `cli_version`, `approved_phases`, and `review_note`. Its schema is `claude-repeat-roster-root-review-v1`. The private receipt path and account usage values remain outside public evidence. Public claims contain only the private receipt hash and the reviewed manifest and controller identities, never usage percentages or credits-off values. Root must review each new private receipt hash and explicitly admit the phase. No account keys or paid overage are part of this lane.

`roster`, `prepare`, and `verify` are offline commands. Preparation wrote immutable manifests for the four Fable configurations; other eligible configurations require their own frozen plans before execution. `smoke` and `development` are the only inference commands. They require an exact manifest hash, reviewed receipt hash, private preflight hash, pinned CLI path, repeat, and condition. The [controller tests](../tests/test_claude_repeat_roster.py) use mocked CLI responses and make no provider calls. The [Fable report tests](../tests/test_build_claude_roster_findings.py) check closed evidence, missing phases, raw-response binding, and root-review binding offline. The [public Fable report](../public-site/claude-roster-repeats.json) keeps subscription billing and quota consumption unknown; CLI list-price estimates are separate from charges. Historical and repeat CLI patch versions differ, and neither serving revision nor effective seed is available.
