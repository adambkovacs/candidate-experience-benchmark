## Public evidence handoff

Operational source files can contain raw provider responses or allocation details. Some linked manifests and journals are already committed; their presence in a particular export depends on its contents. The public reporter reproduces its findings from the sanitized export and does not require those original operational files in a relocated archive. After a terminal stage is independently reviewed, an operator may run the reporter's `--prepare-export medium` or `--prepare-export xhigh` mode against the original checkout. That mode first runs the frozen original interruption verifier and the continuation's strict closed-stage verifier. For an aborted suffix it instead verifies the exact saved prefix, raw captures, journal, claim, reviewed request list, and known child settlements without treating the phase as closed. It then creates **new** `public-evidence-v1` files for that configuration:

- `prefix.positions.jsonl` and `suffix.positions.jsonl` contain record and attempt IDs; request, input and instruction hashes; predictions and status; billing and unknown-cost flags; observed and reserved amounts; provider-reported token totals; returned model/provider; finish reason or error type; reference-isolation flag; and client timing. They omit request text, raw responses and error bodies. The failed original attempt remains a row with no prediction or observed charge. Xhigh also gets a separate `p1.positions.jsonl` for its eight saved P1 responses.
- `request-projection.json` contains the 60 original P0 and P1 request IDs and hashes, with the frozen plan and continuation manifest hashes. It omits request text and budget caps.
- `export-manifest.json` binds the public files to hashes of the private files verified at export time. It records whether the P0 suffix and P1 development were `phase_completed`, `phase_aborted`, or not dispatched, plus saved counts. It contains no private file contents or quota values.

The export is a **candidate**, not approval for publication. A reviewer must inspect it for private fields and write `public-evidence-v1/privacy-review.json` containing `{"schema":"qwen27-v2-interrupted-continuation-findings-v1-privacy-review","approved":true,"export_manifest_sha256":"<SHA-256 of export-manifest.json>","reviewer":"<name>"}`. The public build rejects a missing or stale review. It also rejects unexpected usage fields, altered frozen request schedules, duplicate IDs, changed hashes, and a claimed 60-position score from an aborted stage. A clean archive can then run `python3 scripts/build_qwen27_interrupted_continuation_findings.py --root /absolute/snapshot --output /absolute/report.json`; every `sourceBindings` path in that output must resolve inside the archive and match its SHA-256.

All agreement counts, when admitted, use the unchanged [AI-authored provisional labels](../data/pilot/proposed_labels.jsonl) only after inference. A match is agreement with those saved labels, not validated performance on real candidate comments. Known observed provider charges are summed separately from the original **$0.047001600 unknown-cost upper bound**. Tokens are provider-reported where present; the saved durations include client transport and recording, not isolated model inference time. This candidate has not produced or published a live feed. The xhigh P1 partial inventory is shown separately and remains unscored.
