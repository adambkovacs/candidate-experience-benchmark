# Prompt experiment execution readiness

Audited offline on 2026-09-23 against the [frozen protocol](PROMPT_VARIANTS.md), current adapters and run registries. No model requests, reference-label reads or prompt edits were made during this audit. This is a readiness snapshot, not permission to start phase two or a reduced experiment roster.

Phase two is not ready to execute. Baseline work remains pending, and the Claude, Codex, OpenRouter paid, local HTTP, AnyJev generated-control and LM Studio SDK adapters expose frozen P0/P1/P2 selectors, with P1/P2 restricted to offline previews. The [protocol](PROMPT_VARIANTS.md#controls-and-execution) requires baseline completion or explicit scope resolution first. Blocked configurations remain open; newer hosted replacements are separate configurations, not substitutes for an existing local P0 in a prompt comparison. Paid non-GPT/Claude OpenRouter calls now have [explicit approval and a $5 total cap](OPENROUTER_COST_REVIEW.md); this does not remove the prompt experiment gates.

## What is already usable

The [candidate manifest](../prompts/variants-v1/manifest.json) matches both prompt files and the current labeling-policy prefix byte hashes. P1 is 1,020 bytes, P2 is 6,472 bytes, and P2 begins with P1 byte-for-byte. These byte lengths are not model token counts. Input/rubric/schema isolation, exclusive output files, per-attempt audit evidence, raw responses, failure accounting and offline evaluation already exist across the relevant runners, with surface-specific differences.

Standalone [Python](../scripts/frozen_prompt_variants.py) and [CommonJS](../scripts/frozen_prompt_variants.cjs) composition utilities are now implemented and tested. They preserve P0, verify the frozen manifest/source/candidate hashes and P2 nesting, and record composition provenance. The Claude single-record and batch runners use the Python composer, and the LM Studio SDK runner uses the CommonJS composer. Codex single-record and batch runners now use the Python composer too. The paid OpenRouter adapter also uses the Python composer with saved endpoint/request snapshots for offline preview. The local HTTP baseline uses the same composer and offline selectors. Other adapters are not connected yet. Claude, Codex, paid OpenRouter, HTTP and SDK P1/P2 live runs reject before authentication, billing or SDK connection while the experiment gates remain incomplete. The [offline paired evaluator](../scripts/evaluate_prompt_variants.py) is also implemented, with strict raw OpenRouter, LM Studio SDK and Claude batch10 request extractors and an explicitly unverified declaration-only mode for other surfaces. Offline tests cover composition, historical parity and failure handling; no phase-two inference has run.

The SDK extractor binds the saved artifact/template evidence, exact instruction role and feedback, returned model identity, resolved load/prediction settings and native reasoning split. It rejects repaired JSON and unsupported evidence contracts. Native template capabilities and parser settings are checked through the runner's pure `configureArtifact` export in a cached offline Node subprocess; Node must be available. Invalid JSON constants such as `NaN` remain recorded output failures, matching JavaScript parsing. Requests without returned configuration or response-split evidence cannot claim verified controls through this extractor; their failures remain preserved in the original run. Synthetic tests cover control tampering, native user-role placement and generation-budget failure. This verifies saved request evidence, not completion of the experiment gates.

Exact SDK token preflight remains unresolved. In installed `@lmstudio/sdk` 1.5.0, `LLMApplyPromptTemplateOpts` exposes only BOS/EOS omission and tool definitions (`dist/index.d.ts:4457`); `applyPromptTemplate` uses the model's internal configuration stack (`dist/index.cjs:17476`). The runner instead supplies a custom prediction template with thinking/effort settings. Counting the default rendered template therefore does not establish the effective request length. Preflight needs an audited rendering of the actual template or a supported configured-template API; private SDK state must not be changed to obtain a count. See the [SDK runner](../scripts/lmstudio_reasoning_benchmark.cjs) for its submitted template controls.

## Claude offline previews

Both Claude runners accept `--prompt-variant P0|P1|P2`, `--parent-baseline-id` and `--variant-preview-output`. Preview mode writes a new, exclusive JSON file containing the composed system instruction, unchanged output schema, exact feedback payload and record order. It performs no authentication or inference and is explicitly marked as an offline artifact. The existing required command arguments still apply; `--output` is not written in preview mode. P1/P2 without a preview destination fail before authentication until the protocol gates are implemented. Omitting all variant flags preserves the existing P0 path without introducing a frozen-bundle dependency.

The [historical parity audit](../results/claude-p0-byte-parity-audit-2026-09-23.json) found all 961 saved single-record policy hashes unchanged across 18 files, including historical max runs and one retry. Those records did not preserve raw system text, so direct byte comparison is unavailable. All 24 saved Opus 5.5 batch system prompts across four effort configurations match byte-for-byte. Historical max inclusion here is an offline compatibility check, not authorization for new max runs.

A real 60-record P2 batch preview was also generated offline: six ordered groups of ten, with no reference labels or generation metadata. This proves request composition only; token fit, model responses, smoke approval and paired-experiment eligibility remain unverified.

## LM Studio SDK offline previews

The SDK runner accepts `--prompt-variant P0|P1|P2`, `--parent-baseline-id` and `--variant-preview-output`. It preserves native DeepSeek user-role placement and the resolved template and prediction controls. It reads artifact metadata but does not import the SDK, connect to a model or verify weight availability. P1/P2 live execution remains blocked; the default P0 path has no frozen-bundle dependency.

The [saved-request parity audit](../results/lmstudio-p0-preview-parity-2026-09-23.json) found exact messages, configuration and order across 540 historical requests from nine complete configurations. Native DeepSeek user-role preservation has a synthetic test; it has no completed historical baseline parity claim. These checks establish composition compatibility, not token fit or paired-experiment eligibility. The roster and counts above remain the earlier audit snapshot; current completion status is recorded in the linked registries.

## Codex offline previews

Both Codex runners expose the same explicit variant, parent-baseline and exclusive-preview options. They append the frozen addition after the complete historical instruction, including its output-format guidance, and before feedback serialization. The recorded role is `cli_combined_prompt`; this does not claim a native system message. Preview input rows must contain exactly `id` and `feedback`. Requested model and effort are configuration metadata, not verified serving identity.

The [Codex parity audit](../results/codex-prompt-variants-offline-audit-2026-09-23.json) checks 17 historical single-record request hashes and six full batch prompts, schemas and record orders. The single-record artifacts do not retain full prompt text, so their evidence is hash parity. The six batch prompts match byte-for-byte. Default P0 execution does not depend on the frozen bundle; live P1/P2 requests remain blocked before authentication. Token fit and the remaining experiment gates are still pending.
