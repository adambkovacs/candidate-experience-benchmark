# OpenJev native P0 fresh repeat admission, 28 September 2026

This plan covers three separate razorback16/OpenJev modes: `openjev-fixed`, `openjev-adaptive` and `openjev-thinking`. It prepares three new 60-record P0 passes for each mode. It does not send an inference request, start the server or download a model. The old outputs remain historical observations, outside the fresh-pass scores and flips.

The [fixed reconciliation](../results/openjev-local-fixed-2026-09-23/reconciliation.json) combines seven initial responses and 53 after a restart. The initial DEV-008 request may have started; its outcome and duration are unknown. [Adaptive](../results/openjev-local-adaptive-2026-09-23/reconciliation.json) and [thinking](../results/openjev-local-thinking-2026-09-23/reconciliation.json) each saved 60 valid responses, but the earlier server's exact prefill-cache state was not recorded. Treating those passes as matched first passes would claim control that the evidence does not establish.

The [candidate manifest](../results/repeatability-v1/openjev-native-fresh-v1/manifest.json) binds the 60 input-only reviews, policy prefix, exact native `/v1/systemone` payload for each mode and ID, saved historical files, source code, and all 13 local model assets. It pins OpenJev source commit `e04794ab36e4f7e6040c2547baecdb2737ce2e79`, MLX artifact revision `a7a81407613811e8ba63af92ac0d852b809e191f`, and the package versions in the [setup audit](../results/openjev/setup-audit.json). Fixed sends `samples=1`, `steps=1`, `think=0`, `sequential=false`; adaptive omits `samples` and uses max four reads at threshold 0.1; thinking sends `samples=1`, `steps=1`, `think=512`, `sequential=false`. The server does not return its actual adaptive reread count. Do not substitute usage tokens for that count.

Each new smoke and development stage starts a fresh pinned local server, enables warmup, and uses the source's exact-prompt prefill LRU with a 16,384-token aggregate limit that retains at least one prompt. Smoke and development are separate restarts so that a root reviewer can inspect the three smoke records before development. This is a declared new service-state policy; it does not recreate the old warm-service cache state. The common native host lock stays held from server start through the last response and shutdown. One request is sent per ID. A started request with uncertain outcome stops the phase and cannot be replayed. The controller saves bounded HTTP body bytes before JSON parsing, keeps intrinsic invalid outputs, and sends no reference labels or prior predictions to the server.

A root-reviewed receipt is required for each stage. It must bind the exact phase, stage, manifest SHA-256, controller SHA-256, predecessor inspection hash, source commit, artifact-manifest hash, and `reference_labels_read: false`. Development also requires a separate approval of the three raw smoke responses and their saved decisions. Nine development stages, each with 60 ordered IDs, are planned. A failed or incomplete stage blocks later stages; it does not become a zero score. Even if all 540 new positions are valid, they are repeated measurements on the same 60 fictional reviews, not 540 independent cases.

The controller records client HTTP elapsed time and returned usage when present. It does not measure pure model inference time, model-loading time, electricity cost or local operating cost. Those remain unknown. The fixed historical DEV-008 duration remains unknown. The local package metadata and exact source and artifact hashes must be rechecked at every admission. The root reviewer must verify the candidate manifest and controller before any server launch.
