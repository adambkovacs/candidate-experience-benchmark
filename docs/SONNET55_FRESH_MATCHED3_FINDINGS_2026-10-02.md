Each cell contains six ten-review requests and 60 valid saved classifications, for 2,160 classifications on the same 60 synthetic reviews. Each score counts reviews whose **four fields all match** the frozen provisional v0.2 references. The added classifier prompt P1 changed the all-four score against P0 by 0 to +1 for low, 0 to +2 for medium, −1 to 0 for high, and exactly 0 for xhigh across matched passes. The decision-procedure prompt P2 changed it by −2 to +1 for low, 0 to +1 for medium, and exactly 0 for high and xhigh. There is no consistent improvement from adding instructions in this series. These are descriptive comparisons on fixed reviews and one observed Claude CLI configuration, not estimates of general model quality or causal prompt effects.

Stable totals can conceal changed answers. Across P0's three passes, low and medium each changed at least one four-field answer on three review IDs, high on one, and xhigh on none. For P1, those counts were two, four, one, and one; for P2, one, zero, two, and one. These are the **union of review IDs that changed across the three pairwise pass comparisons**, not counts of independent observations. The feed lists the IDs and field-level changes. For example, xhigh retained 58/60 on every cell while P1 changed review `DEV-006` and P2 changed `DEV-030` between some passes. Medium P2 kept 57/60 with no four-field answer changes across its passes.

The low-effort, pass-1 P0 smoke has a distinct history. Its original attempt ended `service_error` when the earlier guard rejected a newly observed built-in Claude plugin. The retained raw response contained valid predictions for the exact requested model. A separate version-2 sidecar admitted **that same raw response offline** under an exact three-plugin guard; it was never dispatched again. The original failure remains visible, and both original evidence and sidecar are hash-bound. Hidden effects of the built-in plugin are not observable, so this is the observed Claude CLI setup rather than a pure model-only test. See the [version-2 continuation protocol](SONNET55_MATCHED3_V2_CONTINUATION_2026-10-02.md).

The report verifies each closed phase against its frozen request plan, root review, terminal journal, raw captures, saved attempts, and records before scoring. Reference labels were excluded from inference and applied offline. The public bundle is a sanitized projection: its mapping binds public hashes to the private-original hashes, while public-only verification recomputes scores from exported records and labels. Private account and quota diagnostics are excluded. The project owner confirmed human checks of all 60 reviews on 2 October 2026; the [v0.2 reference key](../data/pilot/proposed_labels.jsonl) remains frozen and provisional, with [proposed revisions](REFERENCE_REVIEW_V1.md) recorded separately.

The CLI-reported API-equivalent list-price estimates total **$3.5429424 for development** and **$0.2625174 for smoke**, or **$3.8054598 combined**. These are pricing comparisons, **not observed subscription charges or measured quota consumption**. The calculation uses Anthropic's [Sonnet 5.5 prices](https://platform.claude.com/docs/en/models/sonnet-5-5/overview): $2 per million input tokens, $10 output, $2.50 five-minute cache writes, $4 one-hour cache writes, and $0.20 cache reads. The Message Batches API discount does not apply to ordinary CLI requests that each contain ten reviews. The feed preserves input, output, cache-write, cache-read, and reported thinking-token counts by cell. It also separates client request time from CLI-reported API duration; neither measures pure model inference time.

The same 60 development reviews recur across all cells. The effective seed, serving revision, Claude CLI internal retries, and built-in plugin prompt effects are not fully observable. These limits and the provisional references constrain the interpretation of score differences and apparent repeatability.
