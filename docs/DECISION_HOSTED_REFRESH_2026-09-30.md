# Decision model hosted-route refresh

> Later 30 September update: the [GLiNER admission brief](GLINER_DECISION_ADMISSION_2026-09-30.md) supersedes the Fastino identity, price and context gaps in this earlier snapshot. It preserves the exact public catalogs and distinguishes the hosted Decide ID from open-weight checkpoints. No inference is admitted by either document.

Checked 2026-09-30, with public OpenRouter GET responses captured at 15:38:34–15:38:48 UTC. This read-only check sent no inference requests, used no API keys, and made no account or billing changes. The raw OpenRouter responses are in [the route audit snapshot](../results/route-audits/decision-hosted-refresh-20260930/responses.json).

## OpenRouter result

The documented model catalog filter is `GET /api/v1/models?output_modalities=decisions`. OpenRouter's API reference lists `decisions` as a valid output modality. The query returned seven entries. None matched Liquid d1, Alibaba's decision preview, Together Tev1, Drex, Fastino GLiNER2.5-Decide, or `fastino/gliner2.5-multi-v1`. The model-details and model-endpoints GET routes returned HTTP 404 for each tested candidate ID. The exact IDs checked are recorded in the snapshot. A public 404 establishes that the tested ID was not found by that OpenRouter route at check time; it does not establish an account-specific entitlement result.

`category=decision` is not the decision-model filter. The documented category enum is a list of text use cases and excludes `decision`; both singular and plural category values returned HTTP 400. The modality spelling is plural: `output_modalities=decision` also returned HTTP 400, while `output_modalities=decisions` returned HTTP 200. The API reference documents the model-details and per-model endpoint GET routes used for exact ID checks ([catalog API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties), [model endpoints API](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model)).

The seven returned IDs were `upstage/solar-decide`, `respan/span-01`, `respan/span-01-lite`, `respan/span-01-lite:free`, `jaredpalmer/kev-4b`, `~typesafe/jev-latest`, and `typesafe/jev-1.13`. Solar is the native Upstage route already checked by the parent task. Its current public record names the versioned provider endpoint `upstage/solar-decide-20260928`, gives a 524,288-token context, $0.05/M input and $0/M output. The existing [saved endpoint response](../results/route-audits/solar-openrouter-endpoint-20260930.json) contains the provider records. OpenRouter's published Decisions API route is `POST https://openrouter.ai/api/alpha/decisions`; its public guide documents the Jev request, not a candidate-specific successful call ([OpenRouter Jev guide](https://openrouter.ai/blog/insights/what-is-jev/)).
