# Gemini CLI credit-default amendment

The [Antigravity CLI reference](https://www.antigravity.google/docs/cli/reference/) lists `useG1Credits` as a boolean setting with system default `false`. The [credits guide](https://www.antigravity.google/docs/cli/credits/) says the off setting restricts fallback to personal AI credits after plan quota runs out. The installed 1.2.10 CLI help lists no credit-use flag. No documented per-command or environment override was found. An absent key therefore has a documented effective value of `false`; a present `true`, `null`, or other non-boolean value must stop execution.

The original v2 Gemini 3.1 Pro low P1 smoke stopped after its schedule claim and before its first model request. Its terminal records zero saved rows, and its prediction, attempt and event files are empty. The original global journal retains that stopped attempt. This amendment permits a separate continuation for that one zero-request condition only. Its outputs and schedule journal live under `billing-default-continuation-v1`. All other 13 conditions retain their original v2 outputs and the global schedule.

The wrapper reads settings before and after every native CLI command, records the observed key state and settings-file SHA-256, and never writes settings. The same hash-bound request previews, model, prompt order, batch membership, agent definition, parsing and stop policy remain in effect. The CLI may serialize away an explicit `false`; the available evidence does not establish which preliminary command did so. The documented default supports an absent key, but does not expose a provider billing receipt for each request. Any observed `true` or non-boolean value stops the run.
